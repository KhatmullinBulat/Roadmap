# Линтеры, форматтеры и проверка типов

## Краткий ответ (30 секунд)

Три разных инструмента: **ESLint** — статический анализ **логики** (неиспользуемые переменные, ошибки React/хуков, запрет `any`, безопасность), **Prettier** — **форматирование** (пробелы, кавычки, переносы), **`tsc --noEmit`** — **проверка типов** отдельно от сборки. Prettier не спорит со стилем — он его определяет; ESLint не должен заниматься форматированием (для этого отключают стилевые правила). В современном стеке многое переехало на быстрые Rust-реализации: **Oxlint** и **Biome** (линт+формат в одном), но ESLint остаётся стандартом из-за экосистемы плагинов (React, a11y, import, typescript-eslint).

## Подробно

### ESLint

```js
// eslint.config.js (flat config, ESLint 9+)
import js from "@eslint/js";
import tseslint from "typescript-eslint";
import reactHooks from "eslint-plugin-react-hooks";

export default tseslint.config(
  js.configs.recommended,
  ...tseslint.configs.recommendedTypeChecked,
  {
    plugins: { "react-hooks": reactHooks },
    rules: {
      "react-hooks/rules-of-hooks": "error",
      "react-hooks/exhaustive-deps": "warn",
      "@typescript-eslint/no-explicit-any": "warn",
    },
  },
);
```

- **`rules-of-hooks`** и **`exhaustive-deps`** — главные для React.
- `eslint-plugin-jsx-a11y` — доступность.
- `import/order`, `import/no-cycle` — архитектура.
- Flat config (ESLint 9) заменил `.eslintrc`.
- Типизированные правила (`recommendedTypeChecked`) — мощнее, но медленнее.

### Prettier

```json
{
  "semi": true,
  "singleQuote": false,
  "printWidth": 100
}
```

- Непререкаемый форматтер: «не спорьте о стиле в ревью».
- Настройки минимальны; интеграция в редактор (format on save).
- **`eslint-config-prettier`** — отключает конфликтующие стилевые правила ESLint.
- Prettier не находит багов — только форматирует.

### TypeScript

- `strict: true` — `noImplicitAny`, `strictNullChecks` и др.
- `tsc --noEmit` в CI — быстрее, чем сборка, но всё равно проверяет.
- `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` — дополнительные строгости (могут быть шумными).
- `tsc -b` — проектные ссылки (монорепо).

### Современные альтернативы

| Инструмент | Что делает | Плюсы |
|---|---|---|
| **Oxlint** | линтер (Rust) | очень быстро, совместим с частью правил ESLint |
| **Biome** | линт + формат (Rust) | один инструмент, быстрый |
| **dprint** | формат | быстрый Prettier-совместимый |

Обычно: Prettier + ESLint для полноты правил, либо Biome/Oxlint как «быстрый слой» в CI.

### Линтер и тесты — разные вещи

Линтер ловит шаблонные ошибки, но не логические. `no-floating-promises` ловит забытый `await`, но не «неверную формулу цены».

### В редакторе и в CI

- Editor: format on save + ESLint fix on save.
- Pre-commit: **lint-staged** + **husky** (или `lefthook`) — только изменённые файлы.
- CI: `eslint .`, `tsc --noEmit`, `prettier --check .`.
- Не блокировать CI полным линтом всего репо, если он медленный — оптимизируйте правила/кэш (`--cache`).

> [!warning] Подвох
> «Prettier заменяет ESLint?» — нет. «ESLint форматирует?» — исторически мог, но сейчас стилевые правила вынесены в Prettier. «Линтер ловит типы?» — нет, это `tsc`.
