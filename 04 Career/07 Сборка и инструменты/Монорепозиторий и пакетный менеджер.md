# Монорепозиторий и пакетный менеджер

## Краткий ответ (30 секунд)

**Монорепо** — несколько пакетов в одном репозитории (app + ui-kit + utils), с общими зависимостями и атомарными изменениями. Инструменты: **workspaces** (npm/pnpm/yarn), **Turborepo** (кэш и оркестрация), **Nx** (генераторы, граф проектов), **pnpm** — экономит диск (content-addressable store, симлинки), строгий `node_modules` (нельзя импортировать «чужой» пакет). Плюсы: переиспользование, единые версии, проще рефакторинг. Минусы: тяжелее CI, границы зависимостей, релизы (Changesets).

## Подробно

### Workspaces

```json
{
  "name": "root",
  "private": true,
  "workspaces": ["apps/*", "packages/*"]
}
```

- `package.json` пакета в `packages/ui` может зависеть `"@acme/ui": "workspace:*"`.
- Установка одна — общий `node_modules` (с учётом стратегии менеджера).

### pnpm

```yaml
# pnpm-workspace.yaml
packages:
  - "apps/*"
  - "packages/*"
```

- **Стор** на диске: одинаковые версии — один раз.
- **Строгий `node_modules`**: пакет видит только свои зависимости (ловит «фантомные зависимости»).
- `pnpm --filter @acme/ui test` — запуск в конкретном пакете.
- `--frozen-lockfile` в CI.

### Turborepo / Nx

- **Кэш задач**: если входные файлы не менялись — тест/сборка берётся из кэша (локально и в remote cache).
- **Граф проектов**: `dependsOn` в `turbo.json`.
- **Nx**: генераторы, `affected`-запуски, модульные границы (`@nx/enforce-module-boundaries`).

```json
// turbo.json
{
  "tasks": {
    "build": { "dependsOn": ["^build"], "outputs": ["dist/**"] },
    "test": { "dependsOn": ["build"], "cache": true }
  }
}
```

### Релизы

- **Changesets** — версии и changelog по пакетам, PR-бот.
- **npm publish** из CI (токен, provenance).
- Для внутренних пакетов можно без публикации: `workspace:*` + сборка по графу.

### Плюсы и минусы

| | Монорепо | Полирепо |
|---|---|---|
| Общие правки | один PR | координировать версии |
| Переиспользование | просто | публикация/версии |
| CI | сложнее (граф, кэш) | проще, но больше репо |
| Границы | нужно дисциплинировать | естественные |
| Тяжесть локальной сетапы | выше | ниже |

### Слои и границы

- `apps/*` может зависеть от `packages/*`, не наоборот.
- Один пакет «всё» — антипаттерн.
- Публичные API пакета — `exports`, внутренности закрыты.

### Частые проблемы

- Две версии React в дереве (peerDependencies/overrides).
- TypeScript `paths` с пакетами: нужно `references`/project references.
- Инкрементальная сборка без кэша — медленно.
- «Связанные» версии вручную — ошибки.

> [!tip] Как отвечать
> «Монорепо — про общий код и атомарные изменения. pnpm + workspaces для структуры, Turborepo/Nx для кэша и графа. Границы между пакетами держим через `exports` и линт-правила».
