# Оптимизация бандла: code splitting и tree-shaking

## Краткий ответ (30 секунд)

Цель — отдать **меньше JS** и **быстрее**. Инструменты: **tree-shaking** (удаление неиспользуемых ESM-экспортов, требует `sideEffects`), **code splitting** (разбиение на чанки: маршруты, динамические импорты, vendor), **минификация** (terser/esbuild/oxc), **сжатие** (brotli/gzip), **анализ** (bundle analyzer, покрытие), **удаление дублей** (одна версия React/lodash), **точечные импорты** (`lodash/debounce`), **исключение полифилов** по `browserslist`. Проверять размер лимитом в CI (`size-limit`), а не «на глаз».

## Подробно

### Tree-shaking

```js
// ✅ статические импорты — можно вырезать
import { debounce } from "lodash-es";

// ❌ тянет всё
import _ from "lodash";
_.debounce(...);
```

- ESM + `"sideEffects": false` (или список CSS-файлов).
- `export *` в barrel-файле не мешает, если бандлер умеет tree-shake и нет side-effect-импортов.
- Динамические `require()`/`import()` с вычисляемым путём — не tree-shakeable.

### Code splitting

```js
// маршрут
const Settings = lazy(() => import("./pages/Settings"));

// по клику
button.addEventListener("click", async () => {
  const { open } = await import("./modal.js");
  open();
});
```

- Чанки: **entry**, **vendor** (стабильные зависимости), **async** (динамические).
- Не дробить на сотни мелких чанков: HTTP/2 снижает цену, но не до нуля (scheduling).
- Правило: «не нужен на первом экране — выноси».

### Minify и сжатие

| Слой | Что | Обычно |
|---|---|---|
| Minify | terser / esbuild / Oxc | имя переменных, удаление whitespace |
| Compress | gzip / brotli | brotli лучше на JS, медленнее |
| Кэш | hash-имена + `immutable` | долгий кэш |

- `brotli` даёт ~20% меньше gzip на JS; CDN обычно делает автоматически.
- Source maps — отдельно, не отдавать в прод публично (если не нужно).

### Дубли зависимостей

```bash
npm ls react
npm ls lodash
```

- Две версии React → `Invalid hook call`.
- Два lodash → двойной размер.
- Решения: обновиться, `overrides`/`resolutions`, единая версия в монорепо.

### Полифилы и browserslist

```json
{ "browserslist": ["> 0.5%", "not dead", "not op_mini all"] }
```

- Узкий диапазон — меньше транспайла и полифилов.
- Современные браузеры: не транспилировать `async/await` в генераторы без причины.

### Анализ

- `vite-bundle-visualizer`, `webpack-bundle-analyzer` — карта размеров.
- **Coverage** в DevTools — какой JS не выполнился.
- `size-limit`/`bundlemon` в CI — запрет роста.
- Сравнить с предыдущей сборкой (diff-вес).

### Импорт «кусками»

```js
// ❌
import moment from "moment";
// ✅ (и лучше сразу замена на date-fns/Temporal)
import debounce from "lodash/debounce";
```

- Для иконок — `import { Check } from "lucide-react"` (tree-shakeable), не `import * as icons`.
- CSS — только нужные компоненты/утилиты.

### Что не поможет

- Удаление комментариев.
- «`uglify` получше» — разница копеечная.
- Хеширование — не уменьшает, только кэширует.
- Полифилы «на всякий случай» — всё это вес.

> [!tip] Как отвечать
> «Сначала анализ: что весит. Потом — tree-shaking, split по маршрутам и динамике, точечные импорты, удаление дублей, узкий browserslist. Сжатие и кэш — вторым слоем. В CI — лимит размера, чтобы не раздувалось незаметно».
