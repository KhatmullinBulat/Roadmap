# Оптимизация загрузки тяжёлых компонентов

## Краткий ответ (30 секунд)

Самый дорогой компонент — тот, что попадает в **первый бандл**. Алгоритм: 1) измерить — Bundle Analyzer, Lighthouse, Coverage; 2) **code-splitting**: `React.lazy` + `Suspense` для не-критичных блоков (модалки, редакторы, карты, графики, страницы); 3) **prefetch на намерение** (hover/`pointerenter`, IntersectionObserver) — чанк уже готов к клику; 4) **уменьшить сам компонент** — тяжёлую библиотеку заменить/лениво импортировать, tree-shaking, виртуализация; 5) **вынести computation** в Worker; 6) **SSR/стриминг** и `Activity` для фоновых вкладок; 7) проверить, что `fallback` не вызывает CLS.

## Подробно

### 1. Определить, что тяжёлое

- **Bundle Analyzer** (`source-map-explorer`, `vite-bundle-visualizer`) — какой пакет весит сколько.
- **Coverage** — сколько JS не исполняется при загрузке.
- **Lighthouse** — LCP/INP/TBT; связи «есть ли реальная проблема».
- **React Profiler** — стоимость рендера, а не только скачивания.

### 2. Code splitting по смыслу

```jsx
const Editor = lazy(() => import("./Editor"));
const Charts = lazy(() => import("./Charts"));

function Page() {
  return (
    <>
      <Header />
      <Suspense fallback={<EditorSkeleton />}>
        <Editor />
      </Suspense>
      <Suspense fallback={<ChartsSkeleton />}>
        <Charts />
      </Suspense>
    </>
  );
}
```

- **Маршруты** — главный выигрыш.
- **Модалки и «по клику»** — грузите при открытии.
- **Тяжёлые библиотеки** — `lazy(() => import("monaco-editor"))`, `import("chart.js")`.
- Каждый `lazy` — отдельный сетевой запрос: не плодите десятки.

### 3. Предзагрузка на намерение

```jsx
const loadEditor = () => import("./Editor");
const Editor = lazy(loadEditor);

<button
  onPointerEnter={loadEditor}   // уже грузится
  onClick={() => setOpen(true)} // мгновенно
>
  Редактировать
</button>
```

Или `IntersectionObserver` для блоков «чуть ниже фолда», `link rel="prefetch"` для следующего шага.

### 4. Уменьшить стоимость самого компонента

- **Tree-shaking**: импортируйте точечно.
  ```js
  // ❌ весь lodash
  import _ from "lodash";
  // ✅
  import debounce from "lodash/debounce";
  ```
- **Замена библиотек**: `moment` → `date-fns`/`Temporal` (следите за размером), `chart.js` → нативные SVG для простых.
- **Виртуализация** больших списков (`@tanstack/react-virtual`).
- **Worker** для парсинга/обчисления.
- **OffscreenCanvas** для графики.

### 5. Обновление через приоритеты

- `startTransition` + `Suspense` — переключение вкладок без блокировки.
- **`Activity`** (React 19.2) — состояние скрытой вкладки сохраняется, эффекты отключаются:

```jsx
<Activity mode={tab === "chart" ? "visible" : "hidden"}>
  <Charts />
</Activity>
```

- `useDeferredValue` — для больших обновлений, которые не должны блокировать ввод.

### 6. Серверная часть

- **SSR/стриминг**: HTML отдаётся, пока JS догружается; Suspense-границы стримятся.
- **App Router / RSC**: тяжёлый рендер на сервере, клиент получает готовый UI (для библиотек, где это применимо).
- **`<link rel="preload">`** для главных чанков, `modulepreload` для зависимостей.

### 7. Подвохи

- **Fallback должен совпадать по размеру** — иначе CLS.
- **Ошибка загрузки** — Error Boundary + retry/перезагрузка (сетевые сбои, устаревший хэш после деплоя).
- **Бессмысленный lazy на первом экране** — увеличит LCP задержкой.
- **Ленивость внутри `render`** — новая функция каждый рендер, утечки.
- **`Suspense` не вокруг** ленивого компонента → ошибка «A React component suspended while rendering…».
- Если после lazy LCP просел, верните критичное в основной бандл и оптимизируйте его, а не прячьте.

### Кейс для ответа

> «В проекте был редактор `monaco-editor` (2.5 МБ) в основном бандле: LCP ~4.2 с. Вынесли в `lazy` + prefetch на hover, заменили `moment` на `formatjs`/`date-fns`, роуты — на `lazy`. Начальный JS −60%, LCP 2.4 с, INP не пострадал.»
