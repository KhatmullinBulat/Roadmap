# Таймер в компоненте — что не забыть

## Краткий ответ (30 секунд)

**Очистить таймер в cleanup-функции `useEffect`** (`clearTimeout`/`clearInterval`), а также при каждом изменении зависимостей эффекта. Иначе: таймер продолжает работать после размонтирования (setState на «мёртвый» компонент, лишние запросы, утечка памяти) и дублируется при повторном запуске эффекта (`setInterval` накапливается). Правильный шаблон:

```jsx
useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id);
}, [/* зависимости */]);
```

Сторонние «ключи»: `useRef` для id, если нужен доступ из обработчика; не хранить id в state (изменение state = ререндер).

## Подробно

### Типичная ошибка

```jsx
// ❌ утечка: интервал живёт после unmount; при deps-изменении — второй интервал
function Clock() {
  const [now, setNow] = useState(Date.now());

  useEffect(() => {
    setInterval(() => setNow(Date.now()), 1000);
  }, []);

  return <p>{new Date(now).toLocaleTimeString()}</p>;
}
```

Что произойдёт: компонент размонтирован — таймер продолжает вызывать `setNow`; React в dev может предупредить, в производстве — просто утечка. В StrictMode (dev) эффект вызывается дважды, поэтому даже без размонтирования легко получить два интервала.

### Правильно

```jsx
function Clock() {
  const [now, setNow] = useState(Date.now());

  useEffect(() => {
    const id = setInterval(() => setNow(Date.now()), 1000);
    return () => clearInterval(id); // cleanup
  }, []);

  return <p>{new Date(now).toLocaleTimeString()}</p>;
}
```

### «Сброс» интервала при изменении параметра

Cleanup срабатывает **перед** повторным запуском эффекта, поэтому `clearInterval` в cleanup достаточно:

```jsx
useEffect(() => {
  const id = setInterval(() => setNow(Date.now()), delay);
  return () => clearInterval(id);
}, [delay]);
```

### Таймер, который нужно запускать/останавливать по кнопке

```jsx
const [running, setRunning] = useState(false);

useEffect(() => {
  if (!running) return;
  const id = setInterval(tick, 1000);
  return () => clearInterval(id);
}, [running]);
```

### Debounce/троттлинг

```jsx
useEffect(() => {
  const id = setTimeout(() => search(query), 300);
  return () => clearTimeout(id);
}, [query]);
```

Каждый ввод перезапускает таймер; предыдущий отменяется cleanup'ом.

### Если нужен id снаружи эффекта

```jsx
const idRef = useRef(null);

const start = () => {
  idRef.current = setInterval(tick, 1000);
};

const stop = () => clearInterval(idRef.current);
```

`useRef` не вызывает ререндер и даёт актуальный id.

### `requestAnimationFrame` — тоже очищать

```jsx
useEffect(() => {
  let raf;
  const loop = () => { update(); raf = requestAnimationFrame(loop); };
  raf = requestAnimationFrame(loop);
  return () => cancelAnimationFrame(raf);
}, []);
```

### Прочие ресурсы в cleanup

- `addEventListener` → `removeEventListener` (или `{ signal: controller.signal }`);
- `IntersectionObserver` → `disconnect()`;
- `fetch` → `AbortController.abort()`;
- подписки на стор → отписка;
- `WebSocket` → `close()`.

> [!warning] Что ожидают на собеседовании
> «Не забыть `clearInterval` в cleanup» — минимум. Плюс: «cleanup вызывается перед каждым повторным запуском эффекта, поэтому дублирования не будет»; плюс: «в StrictMode dev-режима эффект монтируется дважды — проверяйте». Можно упомянуть `useEffectEvent` из React 19.2, чтобы таймер не перезапускался из-за него.
