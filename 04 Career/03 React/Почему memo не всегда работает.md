# Почему memo не всегда работает

## Краткий ответ (30 секунд)

`React.memo` пропускает ререндер только при **поверхностном равенстве всех пропсов** и при условии, что **собственный state/context** компонента не изменился. На практике он «не работает», потому что: 1) родитель передаёт **новые ссылки** — объекты, массивы, inline-функции, JSX-элементы; 2) используются **стабильные на вид, но новые каждый рендер** значения (`style={{}}`, `data={items.filter(...)}`); 3) компонент подписан на **context**, который изменился; 4) внутри есть **свой state или подписка на store**; 5) `memo`-компонент вложен в **не-memo родителя** без мемоизации, и сам родитель перерендеривается вместе с ним; 6) сравнение по умолчанию — **shallow**, а нужна глубокая логика (но `React.memo` с кастомным компаратором — ручной код).

## Подробно

### Как `memo` решает

```jsx
const Row = React.memo(RowInner);
// ререндер, если хотя бы один пропс !== предыдущего (Object.is)
```

Если новый объект — это не сравнение по полям, а по ссылке, `memo` видит «изменение».

### Причина 1. Новые ссылки каждый рендер

```jsx
// ❌ каждый рендер: новый объект и новая функция
<Row style={{ padding: 8 }} onSelect={() => select(id)} />

// ✅ стабильные
const style = useMemo(() => ({ padding: 8 }), []);
const onSelect = useCallback(() => select(id), [id]);
<Row style={style} onSelect={onSelect} />
```

Но помните: `useMemo`/`useCallback` в родителе с собственными зависимостями — тоже меняются; мемоизация переносится на другой уровень.

### Причина 2. История с context

```jsx
const ThemeContext = createContext("light");
const Row = React.memo(RowInner);

function App() {
  const [theme, setTheme] = useState("light");
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}> {/* новый объект */}
      <Row />
    </ThemeContext.Provider>
  );
}
```

`value` — новый объект каждый рендер → все потребители контекста перерендерятся, `memo` не спасёт. Решения: стабилизировать `value` (`useMemo`), разделить контексты, использовать селекторы/стор.

### Причина 3. `memo` не спасает от родителя

`memo` пропускает ререндер **своего** компонента, но новый элемент в родителе всё равно создаётся. Если пропсы не изменились, `memo` вернёт `true` и React переиспользует поддерево без вызова функции — собственно для этого он и нужен.

### Причина 4. Свои state/подписки

```jsx
const Row = React.memo(function Row() {
  const [hover, setHover] = useState(false);
  return <li onMouseEnter={() => setHover(true)} />;
});
```

Любой локальный `setState`/контекст/подписка/родитель `memo` — вызывают ререндер независимо от `memo`.

### Причина 5. Компаратор

```jsx
const Row = React.memo(RowInner, (prev, next) => {
  return prev.item.id === next.item.id && prev.item.title === next.item.title;
});
```

Компаратор вернул `true` — ререндер **пропущен**. Если сравнение неверное (например, забыли поле), UI будет устаревшим. Это цена ручного сравнения.

### Причина 6. Дети и `children`

```jsx
<Parent>
  <Child />
</Parent>
```

`<Child />` создаётся в родителе каждый рендер как новый элемент. Если `Parent` перерендерится, новый элемент всё равно попадёт в сравнение; `memo` на `Child` спасёт только при стабильных пропсах. Сложный случай — когда `children` взят из внешнего компонента: он «замораживается» в элементе и не перерендерится вместе с `Parent`.

### Решения

1. **Мемоизировать сложные вычисления** `useMemo`, а не результат вложенных вызовов.
2. **Стабильные `value` контекста** и разделение контекстов.
3. **Один `useCallback`/`useMemo` на комплект пропсов**, переданный в один `memo`.
4. **React Compiler** (React 19+) автоматически мемоизирует компоненты и значения — часто `memo`/`useMemo` больше не нужны.
5. **Профилировать**: React DevTools Profiler + `why-did-you-render`/Highlight updates; не оптимизировать без измерения.
6. **Компонентная граница**: вынести «тяжёлое» в отдельный `memo`-компонент, у которого только примитивные/стабильные пропсы.

> [!tip] Как отвечать
> «`memo` сравнивает пропсы по ссылке. Если в них объект, массив или функция — сравнение всегда «изменилось». Плюс контекст и локальный state. Поэтому либо стабилизируем пропсы (`useCallback`/`useMemo`), либо используем React Compiler, либо не оборачиваем вслепую».
