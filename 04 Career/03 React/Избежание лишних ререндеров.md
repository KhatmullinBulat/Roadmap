# Избежание лишних ререндеров

## Краткий ответ (30 секунд)

Сначала понять, **почему** ререндер происходит: state/пропсы/контекст/подписка на стор/батчинг. Основные инструменты: **стабильные пропсы** (`useMemo`/`useCallback`, примитивы вместо объектов), **`React.memo`** на тяжёлых поддеревьях, **композиция через `children`** (чтобы дети не ререндерились вместе с обёрткой), **локализация состояния** (чем ниже state, тем меньше перерисовок), **разделение контекстов**, **селекторы** в сторах, **`useDeferredValue`/`startTransition`** для тяжёлых обновлений, **виртуализация**. И измерять: Profiler + Highlight updates.

## Подробно

### 1. Где живет state

Чем ниже в дереве состояние, тем меньше затронутых компонентов:

```jsx
// ❌ ввод в поле ререндерит всю страницу
function Page() {
  const [query, setQuery] = useState("");
  return <><Search value={query} onChange={setQuery} /><HeavyList /></>;
}

// ✅ изолированный компонент
function Search() {
  const [query, setQuery] = useState("");
  return <input value={query} onChange={(e) => setQuery(e.target.value)} />;
}
```

### 2. Композиция через `children`

```jsx
// ❌ каждый тик таймера перерендерит и Layout, и HeavyList, если он внутри
function Layout() {
  const [tick, setTick] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setTick((t) => t + 1), 1000);
    return () => clearInterval(id);
  }, []);
  return (
    <>
      {tick}
      <HeavyList />
    </>
  );
}

// ✅ HeavyList передан в children и не ререндерится вместе с Layout
function Layout({ children }) {
  const [tick, setTick] = useState(0);
  ...
  return <>{tick}{children}</>;
}
// <Layout><HeavyList /></Layout>
```

`children` — это элемент, созданный в родительском компоненте. При ререндере `Layout` сам элемент `children` не пересоздаётся, поэтому тяжёлый ребёнок не рендерится.

### 3. `React.memo` на границах

Оборачивать **тяжёлые** элементы со стабильными пропсами. Не оборачивать мелкие листья — экономия нулевая.

### 4. Стабильные пропсы

```jsx
const config = useMemo(() => ({ pageSize: 20 }), []);
const onSave = useCallback(() => save(form), [form]);
<List config={config} onSave={onSave} />
```

Или передавайте примитивы (`id`, `isActive`), а обработчики — на уровень контейнера.

### 5. Контексты

- Разделять на «часто меняется» / «редко меняется» / «dispatch».
- `value` мемоизировать.
- Для частых обновлений — внешний стор с `useSyncExternalStore` (Zustand, Redux).

### 6. Стор с селекторами

```jsx
const count = useStore((s) => s.count); // ререндер только при изменении count
```

`useSelector` сравнивает по ссылке; `shallowEqual` — по полям; `useSyncExternalStore` — для своих сторов.

### 7. Тяжёлые обновления

```jsx
const [isPending, startTransition] = useTransition();
startTransition(() => setQuery(q)); // низкоприоритетно
const deferred = useDeferredValue(query); // старые данные видны, пока рендерится новое
```

Для больших списков — **виртуализация** (`@tanstack/react-virtual`, `react-window`), а не «мемоизируем 5000 строк».

### 8. Ключи и размонтирование

- Стабильные `key` (id) не дают пересоздавать поддерево.
- `key` по индексу при сортировке = пересоздание/сбивание состояния.
- Смена `key` **намеренно** сбрасывает состояние.

### 9. Что на самом деле не ререндер

```jsx
const ref = useRef(0);
ref.current++; // не ререндер

const obj = { x: 1 };
obj.x = 2; // не ререндер (мутация)
setState(prev => prev); // React может bail out
```

`useState` с тем же значением (`Object.is`) — bail out; `useReducer` без изменения — тоже.

### 10. DevTools

- React DevTools → **Profiler** → «Highlight updates» — видно, что ререндерится.
- **Why did this render?** — причина: props/state/context/hooks.
- `why-did-you-render` — логи в консоль.
- Performance → Flame chart — реальная стоимость ререндера.

### Порядок работы

1. Измерить (Profiler).
2. Найти «горячий» компонент.
3. Проверить причины: props (новые ссылки), context, state, store.
4. Уменьшить область (state вниз, `children`), стабилизировать ссылки, `memo` на границе.
5. Переизмерить.
6. Если можно — включить React Compiler: он сам вставит мемоизацию.

> [!warning] Не оптимизируйте всё
> «Обернуть всё в `memo`» — антипаттерн: код хуже, выгоды ноль, а иногда хуже (сравнение пропсов на каждом рендере). Начинайте с измерений, а не с обёрток.
