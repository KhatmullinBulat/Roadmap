# Какой классовый компонент до сих пор используется в React

## Краткий ответ (30 секунд)

**Error Boundary** — единственный «полноценный» паттерн, для которого до сих пор нет функционального аналога в публичном API: `getDerivedStateFromError` и `componentDidCatch` определяются только в классе. Всё остальное (жизненный цикл, state, `this`) перекрыто хуками. Формально классы поддерживаются и сейчас, но новые компоненты пишут функциями, а `memo`/`Suspense`/Boundary-исключения — обычные функциональные.

## Подробно

### Error Boundary

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };

  static getDerivedStateFromError(error) {
    return { hasError: true };
  }

  componentDidCatch(error, info) {
    reportError(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) return <Fallback />;
    return this.props.children;
  }
}
```

Ловит ошибки рендера/жизненного цикла/конструктора **дочерних** компонентов. Не ловит:
- ошибки в своих же `render`;
- асинхронные ошибки (`setTimeout`, промисы);
- ошибки в обработчиках событий;
- SSR-ошибки.

Для функций есть библиотеки (`react-error-boundary`), но внутри — всё тот же класс.

### Что ещё «классовое», но не как паттерн

- `React.Component`/`PureComponent` — работают, но в новом коде не нужны.
- `createClass` — удалён с React 16.
- Legacy: `componentWillMount`, `UNSAFE_*` — удалены/устарели.
- Некоторые сторонние библиотеки (старые UI-киты, HOCs) ещё отдают классы.

### Что стоит упомянуть

- В React 19.2 `Activity` и новые API не требуют классов.
- React Compiler (2024–2025) автоматически мемоизирует функции — классы ему не нужны.
- В документации React сейчас прямо рекомендуют функции; классы — для Error Boundary или legacy.

> [!tip] Как отвечать
> «Функциональный Error Boundary нет: граница ошибок требует `getDerivedStateFromError`/`componentDidCatch`, а это методы класса. Всё остальное — хуки. Формально классы живы, но граница ошибок — главный живой кейс».
