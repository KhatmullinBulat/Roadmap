# Что такое Virtual DOM

## Краткий ответ (30 секунд)

**Virtual DOM** — это лёгкое JavaScript-представление UI (дерево объектов `ReactElement`), которое React строит при рендере. При изменении состояния React создаёт новое дерево и **сравнивает** его с предыдущим (**reconciliation**, diffing), а затем применяет к реальному DOM минимальный набор операций. Смысл: DOM-операции дороги, а сравнение деревьев в памяти дешевле; заодно React даёт декларативную модель («опиши, как должно быть») вместо ручных мутаций. В React 16+ сравнение и применение разнесены по времени — это **Fiber**.

## Подробно

### Как это работает

```jsx
const vnode = <button className="primary">Купить</button>;
// → { type: "button", props: { className: "primary", children: "Купить" } }
```

1. **Render-фаза**: компонент вызывается, возвращает новое дерево элементов.
2. **Reconciliation**: React сопоставляет новое дерево с текущим (Fiber-деревом).
3. **Commit-фаза**: изменения применяются к DOM одним пакетом.

### Алгоритм диффинга (O(n))

Наивное сравнение двух деревьев — O(n³). React использует эвристики:
- **Разные типы на одном месте** → пересоздать поддерево целиком.
- **Одинаковые типы** → обновить только пропсы/атрибуты.
- **Списки** → сравнение по `key`; без `key` — по индексу, что ломается при вставке/удалении.

```jsx
// ❌ по индексу: удаление первого элемента сдвигает индексы
items.map((item, i) => <Row key={i} item={item} />)

// ✅ по стабильному id
items.map((item) => <Row key={item.id} item={item} />)
```

### Отличие от «настоящего» DOM

| | Реальный DOM | Virtual DOM |
|---|---|---|
| Где | браузер, C++ | память, JS-объекты |
| Дешевизна | дорогие операции | обычные объекты |
| Состояние | `scrollTop`, фокус, InputValue | не хранит |

Важно: VDOM не «ускоряет всё». Он даёт **управляемую** производительность и декларативность; для тривиальных случаев ручной DOM может быть быстрее.

### Fiber

С React 16 виртуальное дерево называется **Fiber tree**: каждый узел — объект с `type`, `props`, `stateNode`, `child`, `sibling`, `return`, ссылками на альтернативное дерево и приоритетом. Благодаря Fiber рендер можно **разбить на единицы работы**, приостановить и продолжить (concurrent rendering), а также отличить render (чистый, можно прерывать) от commit (применение к DOM, нельзя).

См. [[Что такое Fiber]].

### Родственные концепции

- **`react-test-renderer`** / Snapshot-тесты используют именно элемент-дерево.
- **`react-dom/server`** рендерит в строку HTML, минуя браузерный DOM.
- **React Native** строит Virtual DOM для native-виджетов — тот же reconciliation, другой «host».
- **Альтернативы**: Svelte компилирует в прямые DOM-операции; SolidJS использует fine-grained реактивность без VDOM.

> [!tip] Как отвечать
> «Virtual DOM — объектное дерево элементов. React сравнивает новое с прошлым по эвристикам (тип, key) и применяет минимум изменений к реальному DOM. Это не про «быстрее всегда», а про декларативность и предсказуемость. В React 16+ оно организовано как Fiber».
