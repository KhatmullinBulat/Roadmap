# Утилитарные типы (Utility Types)

## Краткий ответ (30 секунд)

Утилитарные типы — встроенные в `lib.es5.d.ts` дженерики, которые **преобразуют** тип: `Partial<T>` (все свойства опциональны), `Required<T>`, `Readonly<T>`, `Pick<T, K>`/`Omit<T, K>` (подмножество/исключение ключей), `Record<K, V>`, `Exclude<T, U>`/`Extract<T, U>` (фильтрация union), `NonNullable<T>`, `ReturnType<F>`/`Parameters<F>`/`ConstructorParameters`/`InstanceType`, `Awaited<T>`, `ThisParameterType`/`OmitThisParameter`. Их можно писать самому — они построены на `keyof`, `extends` и mapped/conditional types.

## Подробно

### Часто используемые

```ts
interface User {
  id: number;
  name: string;
  email?: string;
}

type Draft = Partial<User>;      // { id?: number; name?: string; email?: string }
type Full = Required<User>;      // email: string
type ReadonlyUser = Readonly<User>; // все readonly

type PublicUser = Omit<User, "id">;
type UserName = Pick<User, "id" | "name">;

type Roles = Record<"admin" | "user", boolean>; // { admin: boolean; user: boolean }
```

### Работа с union

```ts
type T = "a" | "b" | "c";

type WithoutA = Exclude<T, "a">; // "b" | "c"
type OnlyB = Extract<T, "a" | "b">; // "a" | "b"

type M = NonNullable<string | null | undefined>; // string
```

`Exclude`/`Extract` построены на распределении conditional types:

```ts
type Exclude<T, U> = T extends U ? never : T;
type Extract<T, U> = T extends U ? T : never;
```

### Функции

```ts
function createUser(name: string, age: number) { return { name, age }; }

type Args = Parameters<typeof createUser>; // [name: string, age: number]
type Result = ReturnType<typeof createUser>; // { name: string; age: number }

type First = Args[0]; // string

async function load() { return { id: 1 }; }
type Data = Awaited<ReturnType<typeof load>>; // { id: number }
```

`Awaited<T>` разворачивает промисы (и вложенные). В комбинации с `ReturnType` — очень часто.

### Построение из самих утилит

```ts
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

// Только «не-функции»
type DataProps<T> = {
  [K in keyof T as T[K] extends Function ? never : K]: T[K];
};

// Все значения по ключу
type ValueOf<T> = T[keyof T];
```

- **`partial`/`required`** — mapped types с `?`/`-?`.
- **`readonly`/mutable** — `readonly`/`-readonly`.
- **`as`** в mapped type — переименование/фильтрация ключей (TS 4.1).
- `Required`, `Readonly`, `Pick` и т.д. — тоже mapped types.

### Практическое применение

```ts
// Состояние формы
type FormState<T> = {
  values: T;
  errors: Partial<Record<keyof T, string>>;
  touched: Partial<Record<keyof T, boolean>>;
};

// Ответ API
type ApiResult<T> = 
  | { ok: true; data: T }
  | { ok: false; error: string };

// Пропсы компонента без id
type CardProps = Omit<Item, "id"> & { onOpen: () => void };
```

### Ловушки

1. **`Partial` — поверхностный.** Вложенные объекты остаются обязательными; для глубокого нужен `DeepPartial`.
2. **`Omit` на union** не распределяется: `Omit<A | B, "x">` сведёт к общим ключам. Нужно распределить:

```ts
type DistributiveOmit<T, K extends keyof any> = T extends any ? Omit<T, K> : never;
```

3. **`Readonly` — не глубокая**, и не влияет на рантайм.
4. **`Record<string, T>`** превращает `keyof` в `string | number`, тогда как литеральные ключи теряются.
5. `Pick`/`Omit` с ключом, которого нет, — ошибка (что хорошо) или `never` в зависимых типах.

> [!tip] Как отвечать
> «Утилитарные типы — это функции над типами. Каждый можно написать самому через keyof/mapped/conditional. Зная 8–10 основных и как устроен mapped type, вы не зависите от вспоминания списка».
