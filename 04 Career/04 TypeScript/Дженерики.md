# Дженерики

## Краткий ответ (30 секунд)

**Дженерик** — параметр типа: функция, класс, интерфейс или алиас работают с «неизвестным, но сохраняемым» типом: `function identity<T>(x: T): T`. Дженерики сохраняют **связь между входом и выходом** и не теряют конкретный тип (`first([1, 2])` → `number`, а не `any`). Ограничение — `T extends {...}` сужает допустимые типы; вывод (`inference`) подставляет тип из аргументов; по умолчанию — `<T = string>`. Главная цель — типобезопасность без дублирования, а не «продвинутость».

## Подробно

### Базово

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}

const n = first([1, 2, 3]);   // number | undefined
const s = first(["a"]);       // string | undefined
```

Без дженерика пришлось бы писать `any` или перегрузки под каждый тип.

### Ограничения (`extends`)

```ts
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

const users = [{ id: 1, name: "Аня" }];
pluck(users, "name"); // string[]
pluck(users, "age");  // ❌ нет такого ключа
```

`K extends keyof T` — не наследование, а **ограничение** множества допустимых ключей.

### Значение по умолчанию

```ts
interface ApiResponse<T = unknown> {
  data: T;
  error?: string;
}

type Users = ApiResponse<User[]>; // T = User[]
const r: ApiResponse = { data: 42 }; // T = unknown
```

### Несколько параметров и связи

```ts
function map<T, U>(items: T[], fn: (t: T) => U): U[] {
  return items.map(fn);
}

map([1, 2], (n) => String(n)); // string[]
```

### Дженерики в классах и хуках

```ts
class Stack<T> {
  private items: T[] = [];
  push(item: T) { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
}

// React
function useLocalStorage<T>(key: string, initial: T): [T, (v: T) => void] { ... }
```

### Вывод и явная передача

```ts
createSet<number>([1, 2]);     // явно
createSet([1, 2]);             // вывод: number
createSet([1, "a"]);           // (number | string) — лучший общий тип
```

Часто вывод «шире», чем хочется:

```ts
function pair<T>(a: T, b: T): [T, T] { return [a, b]; }
pair("a", 1); // [string | number, string | number]
```

Для этого и добавляют `NoInfer<T>` (TS 5.4) или отдельные параметры.

### Ограничение типами-значениями

```ts
function get<T extends object, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
```

### Типовые паттерны

- **Builder** с дженериками.
- **`Result<T, E>`** / **`Promise<T>`** — параметр «успех/ошибка».
- **`Record<K, V>`** — дженерик под ключ/значение.
- **Utility types** (`Partial<T>`, `Pick<T, K>`) — все они дженерики.
- **Conditional types** с `infer`.
- **`<T extends (...args: any[]) => any>`** для функций-обёрток.

### Антипаттерны

```ts
// ❌ дженерик не используется
function log<T>(msg: T) {}
// ✅
function log(msg: unknown) {}
```

Дженерик без связи в сигнатуре — просто `unknown`/`any` с декором. `any` в ограничении (`T extends any`) тоже бесполезен.

> [!tip] Как отвечать
> «Дженерик — параметр типа, который сохраняет связь и конкретику. `extends` у него — ограничение, не наследование. Полезен там, где нужно вернуть тот же тип/ключ, который передали (`T[K]`, `keyof`)».
