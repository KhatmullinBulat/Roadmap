# Асинхронные компоненты

## Краткий ответ (30 секунд)

**`defineAsyncComponent(() => import("./Heavy.vue"))`** — компонент загружается **по требованию**: пока чанк не загружен, показывается `loadingComponent`/ничего, при ошибке — `errorComponent`. Это **code splitting** на уровне компонентов: меньше начальный бандл. Работает с `Suspense` (асинхронная загрузка), с `KeepAlive`/`Transition`. В Vue 3.5+ есть параметр `hydrate` для SSR: сначала серверный HTML, затем подгрузка JS. Не путать с «async `setup`» (это асинхронная инициализация, а не загрузка кода).

## Подробно

### Базовое использование

```js
import { defineAsyncComponent } from "vue";

const Chart = defineAsyncComponent(() => import("./components/Chart.vue"));
```

```vue
<Suspense>
  <Chart :data="points" />
</Suspense>
```

### С опциями

```js
const Editor = defineAsyncComponent({
  loader: () => import("./Editor.vue"),
  loadingComponent: Spinner,
  errorComponent: LoadError,
  delay: 200,        // не показывать спиннер дольше 200мс
  timeout: 10_000,   // ошибка таймаута
  onError(error, retry, fail, attempts) {
    if (attempts <= 3) retry();
    else fail();
  },
});
```

- `delay` — не «мигать» спиннером на быстрой сети.
- `timeout` — не висеть вечно.
- `retry` — повторная загрузка чанка (частый сбой на плохой сети/старом хэше после деплоя).
- SSR: `hydrate`-опции (3.5+) — серверный HTML получает значение сразу, клиент гидрирует.

### Что даёт

- Уменьшение initial bundle (см. [[Оптимизация бандла]]).
- Компонент становится отдельным чанком.
- С фолбэком — не блокирует первый рендер.

### Что не стоит делать

- Асинхронно грузить то, что нужно на первом экране (хуже LCP).
- Делать асинхронными мелкие компоненты — десятки запросов.
- Забывать `errorComponent`: сбой загрузки чанка = белый блок.
- Использовать `defineAsyncComponent` внутри `setup` каждого рендера (создание нового компонента).

### Suspense и async setup

```vue
<script setup>
const data = await fetchData(); // нужен <Suspense> в родителе
</script>
```

- Это не загрузка кода, а ожидание данных.
- В Nuxt `useAsyncData` + `<Suspense>`/`<NuxtPage>` работают «из коробки».
- Без `Suspense` async `setup` не отрендерится (ошибка).

### Асинхронный компонент и `KeepAlive`

- Async-компонент внутри `KeepAlive` кэшируется после загрузки; повторный вход — `activated`.
- При переключении до загрузки — может быть пусто/фолбэк.

### Частый кейс

Тяжёлый редактор/график в модалке:

```vue
<template>
  <button @click="showEditor = true">Редактировать</button>
  <Suspense v-if="showEditor">
    <AsyncEditor @close="showEditor = false" />
  </Suspense>
</template>
```

Чанк грузится только после клика; параллельно можно **prefetch** на `pointerenter` через `import()` (см. [[React.lazy и Suspense]] — идея та же).

> [!tip] Как отвечать
> «`defineAsyncComponent` — ленивый чанк на уровне компонента. С `delay`/`timeout`/`errorComponent`, при SSR — `hydrate`. Асинхронный `setup` — про данные и `Suspense`, это другое».
