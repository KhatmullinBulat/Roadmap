# key в v-for

## Краткий ответ (30 секунд)

`key` — **стабильный идентификатор элемента в списке**. Vue использует его, чтобы понять, какой узел остался тем же при перестановке/вставке/удалении, а какой новый. Без `key` (или с индексом) Vue переиспользует узлы **по позиции** — состояние дочерних компонентов, фокус, чекбоксы, введённые значения «съезжают» на чужие элементы. Правило: `key` должен быть **уникальным и стабильным** (id из данных), не индексом и не `Math.random()`. Меняя `key` намеренно, можно **принудительно пересоздать** компонент (сброс формы/состояния).

## Подробно

### Что происходит без ключа по индексу

```vue
<!-- ❌ индекс как ключ -->
<li v-for="(item, i) in items" :key="i">
  <input v-model="item.title" />
</li>
```

Если удалить первый элемент, Vue сопоставит по индексу и «переложит» данные/состояние на предыдущие узлы: DOM-инпуты (неконтролируемые, фокус) и локальный стейт дочерних компонентов окажутся не у тех данных.

```vue
<!-- ✅ стабильный id -->
<li v-for="item in items" :key="item.id">
```

### Почему `<key>` нужен именно в `v-for` и при смене типов

- Для списков — сопоставление identity.
- Для условных веток `v-if`/`v-else` **одного элемента** с разным содержимым — чтобы Vue не переиспользовал узел:

```vue
<component :is="isLogin ? LoginForm : RegisterForm" :key="isLogin ? 'login' : 'register'" />
```

Без `key` форма может «сохранить» введённые данные при переключении — классический баг.

### Хороший и плохой ключ

| Ключ | Оценка |
|---|---|
| `item.id` | ✅ |
| составной `\`${type}-${id}\`` | ✅ если уникален |
| индекс `(item, i) => i` | ⚠️ только для статичных неинтерактивных списков |
| `Math.random()` / `Date.now()` | ❌ всё пересоздаётся каждый рендер |
| поле, которое меняется | ❌ постоянные пересоздания |

### key как инструмент

```vue
<!-- Принудительный ремаунт при смене пользователя -->
<UserProfile :key="userId" :user="user" />

<!-- Сброс формы -->
<OrderForm :key="formVersion" />
```

Это нормальный приём: меняется `key` — Vue удаляет старый узел и создаёт новый (все хуки, состояние — заново).

### Связано с производительностью

- Стабильные ключи → меньше патчей DOM, точный diff.
- `key` на индексе → иногда Vue «переносит» все узлы, что дорого и/или ломает состояние.
- Не путать: `key` не делает список виртуальным; для тысяч строк — виртуализация.

> [!warning] Подвох
> «Почему чекбоксы “переехали” после сортировки?» — ключ был индексом. При сортировке Vue переиспользует DOM-узлы по позициям, а `checked` (DOM-состояние) остаётся у позиции, не у элемента.
