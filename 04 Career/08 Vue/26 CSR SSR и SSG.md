# CSR, SSR и SSG

## Краткий ответ (30 секунд)

- **CSR** — сервер отдаёт пустой HTML + JS, контент рендерит браузер. Просто, но «белый экран» до загрузки JS, хуже LCP/SEO.
- **SSR** — сервер рендерит HTML под конкретный запрос (актуальные данные), браузер гидрирует. Быстрый первый контент, SEO, но дороже сервер (CPU/кэш) и есть «hydration»-риски.
- **SSG** — HTML **заранее** на сборке (для каждой страницы/параметра). Самый быстрый и дешёвый, но данные на момент сборки; обновление — rebuild/ISR-подобные механизмы.

В Nuxt режимы настраиваются (`ssr: true/false`, `nitro.prerender`, route rules с `prerender`/`ssr: false`/`isr`) и сочетаются по маршрутам (hybrid rendering).

## Подробно

### Сравнение

| | CSR | SSR | SSG |
|---|---|---|---|
| HTML с контентом | после JS | сразу | сразу (из сборки) |
| Первый экран | медленный (пустой) | быстрый | самый быстрый |
| SEO | зависит от рендера | хороший | хороший |
| Данные | всегда свежие | свежие на запрос | на момент сборки |
| Сервер | только статика | нужен Node/edge | статика/CDN |
| Гидратация | да | да | да |
| Стабильность | просто | сложнее (window, данные) | просто |
| Стоимость | низкая | выше | самая низкая |

### CSR в Nuxt

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  ssr: false,            // весь сайт CSR (SPA)
  routeRules: {
    "/admin/**": { ssr: false }, // только раздел
  },
});
```

- Для админок/дашбордов, где SEO не важен и интерактивность — суть.
- Внимание: `useFetch` на клиенте — запрос идёт после загрузки; первый рендер пустой.

### SSR

- Сервер выполняет `setup`, `useAsyncData`, рендерит HTML, отдаёт с payload.
- Браузер гидрирует (повторяет тот же рендер без запроса, используя payload).
- Плюсы: LCP, SEO, OG-теги, персонализация.
- Минусы: нет `window`/`document`, нужен сервер, кэш/A-B.

### SSG (prerender)

```ts
routeRules: {
  "/blog/**": { prerender: true },     // статические страницы
  "/product/**": { isr: 60 },          // инкрементальная регенерация (на сервере)
  "/dashboard": { ssr: false },
},
```

- `nuxi generate` — статический сайт.
- Список URL для prerender (`nitro.prerender.routes`, `crawlLinks`).
- «ISR» в Nuxt — кэш на сервере с `swr`/`isr` (не как Next, но похоже по смыслу).

### Hybrid

В Nuxt гибридная модель: маркетинг — SSG, аккаунт — SSR, админка — CSR, всё в одном приложении. Это **не** «выбрать один режим навсегда».

### Практический выбор

- Контент/маркетинг/блог → SSG (+ ISR при большом объёме).
- E-commerce каталог → SSR/ISR (свежие цены, SEO).
- Админка/личный кабинет → CSR (или SSR для первой страницы).
- Лендинги → SSG/статика.

> [!tip] Как отвечать
> «CSR — пустой HTML и всё в браузере. SSR — HTML под запрос, быстрее LCP и SEO, но сервер. SSG — заранее на сборке, дешево и быстро, данные на момент сборки. В Nuxt это route rules и можно смешивать».
