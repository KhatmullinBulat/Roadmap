# Доступ к дочернему компоненту: template ref

## Краткий ответ (30 секунд)

Получить экземпляр дочернего компонента можно через **template ref**: `<Child ref="childRef" />` + `const childRef = ref()` → после `onMounted` в `childRef.value` экземпляр. В `<script setup>` доступны **только** то, что дочерний компонент явно открыл через **`defineExpose({ focus, reset })`** — приватность по умолчанию. Риски: императивные вызовы ломают односторонний поток и тестируемость, зависят от внутренностей; компонент может быть `null` до монтирования/после размонтирования; в `KeepAlive`/`v-if` — усложняется. Предпочтительнее — **пропсы/события/слоты**, а ref — для «императивных» API: `focus()`, `scrollTo()`, `open()`, интеграция с не-Vue DOM.

## Подробно

### Базовый синтаксис (Vue 3.5+)

```vue
<script setup>
import { useTemplateRef, onMounted } from "vue";

const child = useTemplateRef("child-ref");

onMounted(() => {
  child.value?.focus(); // метод, открытый через defineExpose
});
</script>

<template>
  <Child ref="child-ref" />
</template>
```

До 3.5:

```vue
<script setup>
const child = ref(null);
</script>
<template>
  <Child ref="child" />
</template>
```

(есть нюанс с TS: `ref<InstanceType<typeof Child> | null>(null)`).

### `defineExpose` в дочернем

```vue
<!-- Child.vue -->
<script setup>
import { ref } from "vue";

const input = ref(null);

function focus() { input.value?.focus(); }
function reset() { input.value.value = ""; }

defineExpose({ focus, reset });
</script>

<template><input ref="input" /></template>
```

- Без `defineExpose` всё «внутреннее» закрыто — это хорошо.
- Открывайте **минимальный** API, не `state`/внутренние refs.

### Нативный DOM-элемент

```vue
<input ref="inputEl" />
```

- `inputEl.value` — DOM-узел, доступен после монтирования.
- `onMounted` — первый момент, когда DOM готов.

### Риски

1. **Нарушение потока данных**: родитель «дёргает» метод ребёнка в обход `emit`/props.
2. **Связанность с реализацией**: переименование/рефакторинг ребёнка ломает родителя.
3. **Жизненный цикл**: `null` до `mounted`, после `v-if=false`, в момент `deactivated`.
4. **`v-for`**: refs — массив; лучше `useTemplateRefsList`/`ref`-массив функций.
5. **SSR**: на сервере `null`; императивные вызовы только в `onMounted`/клиентских хуках.
6. **Нельзя** «читать состояние» ребёнка и полагаться на синхронизацию — это делает родителя хрупким.

### Когда ref оправдан

- Управление фокусом (`focus()` в модалке/автокомплите).
- Императивные API с большим состоянием: `scrollTo`, `open`, `validate`, `reset`.
- Интеграция с не-Vue библиотекой (видеоплеер, редактор, карта).
- Измерения DOM (`getBoundingClientRect`).

### Когда — не ref

- Смена данных — `props`/`emit`/`v-model`.
- «Родитель должен знать, что ребёнок открылся» — `emit("update:open")` или `v-model:open`.
- Общие данные — стор/композабл.

### `$refs` в Options API

```js
this.$refs.child.focus();
```

То же самое, но без типизации; `ref="child"` в шаблоне. Не использовать в `<script setup>` (`$refs` недоступны).

### `provide`-ссылка как альтернатива

Если несколько уровней, можно `provide`-нуть функцию управления (не весь экземпляр) — тот же риск, но контролируемый.

> [!tip] Как отвечать
> «Ref — императивный выход: focus/scroll, только через `defineExpose`. Данные — через props/emit. Риски — хрупкость и зависимость от внутренностей; поэтому открываю минимум и не дергаю state».
