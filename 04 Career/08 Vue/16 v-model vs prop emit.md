# v-model vs prop + emit

## Краткий ответ (30 секунд)

`v-model` — **соглашение** о двусторонней связи: prop `modelValue` + событие `update:modelValue`, разворачиваемое в атрибуты. Явная схема — любой prop и любое событие (`:value` + `@change`), где родитель сам решает, когда и как обновлять состояние. Технически `v-model` — это частный случай «prop + emit», но с готовым именованием и sugar. **Явный вариант лучше**, когда: значение нужно валидировать/преобразовывать, связь не симметрична (ребёнок «предлагает», родитель «принимает»), несколько связанных prop/событий, `v-model` смешал бы «внутреннее» и «внешнее» состояние. `v-model` лучше для простых полей/компонентов формы.

## Подробно

### Один и тот же контракт

```vue
<Input v-model="name" />
<!-- = -->
<Input :model-value="name" @update:model-value="name = $event" />
```

```vue
<Input :value="name" @change="onNameChange" />
```

Разница — в **семантике и контроле**, не в возможностях.

### Когда `v-model`

- Компонент формы («управляемое значение»): `DatePicker`, `Select`, `Slider`.
- Нужна простая симметрия: «показать и обновить».
- Несколько значений с именованными `v-model:*` (3.4+ `defineModel`).
- UI-кит-конвенция.

### Когда явно (`prop` + `emit` события-действия)

```vue
<!-- ребёнок только сообщает о намерении -->
<textarea :value="text" @input="onInput" />
<button @click="emit('submit', { text, touched: true })">Отправить</button>
```

Родитель:

```vue
<Editor
  :text="draft"
  @input="draft = $event"
  @submit="save"
  @validate="validate"
/>
```

- **Бизнес-правило**: не обновлять состояние, пока не прошла валидация (`change` → «попробовать сохранить»).
- **Событие — не значение**: `@submit`, `@cancel`, `@request-reset`.
- **Асинхронное подтверждение**: родитель делает optimistic update/запрос и откатывает при ошибке.
- **Разные направления**: `modelValue` — данные, а `error` — сообщение родителя.

### Сравнение

| | `v-model` | явный prop+emit |
|---|---|---|
| Контракт | фиксированный (`modelValue`) | какой угодно |
| Скорость написания | высокая | ниже |
| Контроль валидации | в компоненте (`set`/`defineModel`) | в родителе |
| Несколько связанных полей | `v-model:a`, `v-model:b` | `:a`/`:b` + свои события |
| Семантика события | «значение изменилось» | может быть действием |
| Риск мутации props | выше (соблазн писать в modelValue) | ниже |

### Гибрид

Можно дать и `v-model`, и событие действия:

```vue
<SearchInput v-model="query" @search="doSearch" />
```

`v-model` синхронизирует ввод, `@search` — намерение искать (Enter/кнопка). Это часто лучше, чем дебаунс внутри компонента, который не знает, какой запрос нужен родителю.

### `defineModel` и валидация

```js
const model = defineModel<string>({
  set(value) {
    if (value.length > 20) return model.value; // вернуть прежнее значение
    return value.trim();
  },
});
```

Но помните: «молча отклонить» — UX-проблема; чаще лучше показать ошибку через отдельный проп/событие.

> [!warning] Подвох
> «Можно ли сделать `v-model` без `update:modelValue`?» — нет, конвенция. Если только `emit("input")` (как в Vue 2) — в Vue 3 `v-model` не сработает.
