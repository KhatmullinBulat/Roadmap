# Как работает реактивность Vue 3

## Краткий ответ (30 секунд)

Vue 3 оборачивает объекты в **`Proxy`**: чтение свойства вызывает `track` — текущий эффект (компонент, `computed`, `watch`) записывается в зависимость; запись — `trigger` — все эффекты-подписчики ставятся в **очередь**. Обновление UI асинхронно: очередь выполняется на **microtask** (отсюда `nextTick`), за один тик — по одному обновлению компонента. `ref` хранит значение в `.value`, для примитивов реактивность через getter/setter; `reactive` возвращает Proxy. `computed` — ленивый производитель с кэшем, пересчитывается только при изменении зависимостей.

## Подробно

### Цепочка

```
state.value = 1               → set trap → trigger(dep)
{{ state }} в шаблоне          → render effect → track(dep)
очередь эффектов → flush на microtask → patch DOM
```

- **`track`** — «этот эффект читает это свойство».
- **`trigger`** — «свойство изменилось, разбуди подписчиков».
- **Версионирование** (`version`) — для `computed`/`ref` в 3.5 добавили счётчики, чтобы не устаревшие зависимости не будили.
- **Alien Signals** — рефактор ядра реактивности в 3.6 (RC на 2026), быстрее и экономнее по памяти; API тот же.

### `ref` vs `reactive` внутри

- `ref(x)` — объект с `.value`, getter/setter вызывает `track`/`trigger`. Для объектов внутри оборачивается в `reactive`.
- `reactive(obj)` — Proxy вокруг объекта; вложенные объекты тоже проксируются **лениво** при чтении.

### Что отслеживается

- Чтение **уже существующего** свойства — да.
- Добавление нового свойства в `reactive` — да (Proxy, в отличие от Vue 2).
- Удаление — да.
- `Map`/`Set`/`WeakMap` — да (через прокси коллекций).
- **Классовые инстансы** — Proxy работает, но методы, меняющие `this`, нужно оборачивать (`reactive(new Store())` + `markRaw` для не-реактивных).

### Батчинг и `nextTick`

```js
count.value++;
count.value++;
// до flush UI не обновился
await nextTick(); // DOM обновлён
```

- Несколько синхронных изменений — один рендер.
- Внутри `await` — разные тики → несколько рендеров.
- `flush: "post"` у `watch` — после DOM-обновления.

### `shallowRef` / `shallowReactive`

- `shallowRef` — реагирует только замена `.value`, вложенные мутации — нет (используется в Nuxt `useAsyncData`, списках, больших данных).
- `shallowReactive` — только верхний уровень.
- `markRaw` — «не оборачивать» (экземпляры классов, сторонние объекты).

### Как отлаживать

```js
import { onRenderTracked, onRenderTriggered } from "vue";

onRenderTriggered((e) => console.log(e.key, e.newValue));
```

- Vue DevTools → компонент → «Reactivity» — кто зависит от кого.
- `effectScope` — группировка эффектов (для композаблов/плагинов).

> [!warning] Подвох
> «Почему UI не обновился сразу после изменения?» — батчинг: DOM патчится в микротаске. Это не баг. «Почему `arr[0] = x` в Vue 2 не работало?» — defineProperty не перехватывал индексы; в Vue 3 — Proxy и работает.
