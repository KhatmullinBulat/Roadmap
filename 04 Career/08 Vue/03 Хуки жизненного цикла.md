# Хуки жизненного цикла Vue 2 и Vue 3

## Краткий ответ (30 секунд)

Хуки описывают этапы: **создание** (`beforeCreate`/`created`), **монтирование** (`beforeMount`/`mounted`), **обновление** (`beforeUpdate`/`updated`), **размонтирование** (`beforeUnmount`/`unmounted`), **активация в KeepAlive** (`activated`/`deactivated`), `errorCaptured`, `renderTracked`/`renderTriggered`. В Vue 3 они вызываются **из `setup`** как `onMounted`, `onUpdated` и т.д. Пропущены уровни, которых нет в Composition API: `beforeCreate`/`created` заменяются самим телом `setup` (оно исполняется до создания компонента). Главное отличие: Vue 2 `beforeDestroy`/`destroyed` → Vue 3 `beforeUnmount`/`unmounted`.

## Подробно

### Таблица соответствий

| Vue 2 (Options) | Vue 3 (Composition) | Когда |
|---|---|---|
| `beforeCreate` | — (тело `setup`) | до инициализации данных |
| `created` | — (после `setup`) | данные готовы, DOM нет |
| `beforeMount` | `onBeforeMount` | до вставки в DOM |
| `mounted` | `onMounted` | DOM готов (refs доступны) |
| `beforeUpdate` | `onBeforeUpdate` | до патча DOM |
| `updated` | `onUpdated` | после патча DOM |
| `beforeDestroy` | `onBeforeUnmount` | до удаления |
| `destroyed` | `onUnmounted` | после удаления (cleanup!) |
| `activated` | `onActivated` | KeepAlive-вход |
| `deactivated` | `onDeactivated` | KeepAlive-выход |
| `errorCaptured` | `onErrorCaptured` | ошибка у потомка |
| `renderTracked` | `onRenderTracked` | dev: чтение зависимости |
| `renderTriggered` | `onRenderTriggered` | dev: изменение зависимости |

```vue
<script setup>
import { onMounted, onUnmounted } from "vue";

onMounted(() => {
  window.addEventListener("resize", onResize);
});

onUnmounted(() => {
  window.removeEventListener("resize", onResize);
});
</script>
```

### Порядок для родителя/ребёнка

- **mounted**: сначала дочерние, потом родитель.
- **unmounted**: сначала родитель, потом дочерние.
- `onUpdated` — после каждого патча, **не** гарантирует, что только ваш компонент обновился (осторожно с `nextTick`).

### `setup` и `created`

`setup` вызывается **до** `beforeCreate`-эквивалента (до инициализации экземпляра), но **реактивность и пропсы уже доступны**. Поэтому:

- fetch в `setup` — «как `created`», но `await` допустим в `script setup` с `<Suspense>`.
- DOM в `setup`/`created` — нельзя, нужен `onMounted`.
- `this` в `setup` — недоступен; используйте `getCurrentInstance()` только в крайнем случае.

### `onMounted` и SSR

На сервере `onMounted` **не выполняется** (нет DOM). В Nuxt `onMounted` — только клиент; `onServerPrefetch`/`useAsyncData` — для данных на сервере (см. [[31 Данные в Nuxt и SSR]]).

### KeepAlive-хуки

`onActivated`/`onDeactivated` — не то же самое, что `mounted`/`unmounted`: компонент не уничтожается и не создаётся заново. Таймеры при `deactivated` надо останавливать вручную.

### Cleanup — правило

Всё, что «подписалось» в `mounted`/`setup`, снимайте в `onUnmounted`/`onBeforeUnmount`:

```js
const controller = new AbortController();
onMounted(() => fetch("/api", { signal: controller.signal }));
onUnmounted(() => controller.abort());
```

Композаблы (см. [[Замыкания]]) должны сами регистрировать cleanup, а не перекладывать на компонент.

### Типичные ошибки

- Требовать DOM в `created`.
- Тяжёлый fetch в `onMounted`, хотя данные нужнее до рендера (SSR/`Suspense`).
- `onUpdated` → `setState` (бесконечный цикл без условия).
- Забыть cleanup → утечка/двойные подписки (в dev `StrictMode`-эквивалента нет, но HMR дублирует).

> [!tip] Как отвечать
> «Монтаж — `onMounted`, очистка — `onUnmounted`, обновление — `onUpdated`. `created` в Composition API нет — это тело `setup`. Vue 2 `beforeDestroy` переименован в `beforeUnmount`».
