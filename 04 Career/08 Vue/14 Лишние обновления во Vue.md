# Лишние обновления во Vue

## Краткий ответ (30 секунд)

Причины: 1) реактивное состояние слишком «высоко» — любое изменение ререндерит большой компонент; 2) `watch` с неправильными зависимостями/`deep: true` на больших данных; 3) `v-if`/списки без `key` или с `key=index` → лишние пересоздания; 4) дорогие `computed`/методы в шаблоне; 5) `reactive`-объект целиком передан как проп; 6) `shallowRef` не используется для больших API-данных; 7) компоненты не разбиты — «god component»; 8) `keep-alive`/`transition` держат лишние экземпляры. Лечение: разбить на компоненты, поднять/опустить состояние, `computed` вместо методов, точные `watch`, стабильные ключи, `shallowRef`/`markRaw`, virtual scroll.

## Подробно

### 1. Границы компонентов

Vue обновляет **компонент целиком** при изменении любого его реактивного состояния. Поэтому:

```vue
<!-- ❌ одно состояние — весь экран перерендеривается -->
<script setup>
const query = ref("");
const items = ref([]); // большой список
</script>
<template>
  <input v-model="query" />
  <HeavyList :items="items" />
</template>
```

- Вввод в `query` ререндерит всё.
- Вынесите `input` в отдельный компонент (`SearchBox`) — ввод не затронет `HeavyList`.
- Или наоборот: держите состояние в дочернем компоненте, если родителю оно не нужно.

### 2. `watch` зависимости

```js
// ❌ deep на огромном объекте — сравнение на каждое изменение
watch(bigState, () => { ... }, { deep: true });

// ✅ следим за конкретными полями/идентификатором
watch(() => bigState.id, () => { ... });
```

- `deep: true` обходит всё дерево — дорого.
- `watch` на `reactive` объект без `deep` **не** реагирует на вложенные мутации (и это часто не то, что хотели) — уточнить намерение.
- `immediate: true` в `watch` ≠ «всё должно обновляться чаще».

### 3. Ключи и `v-if`

- `key=index` при сортировке/удалении → пересоздание и потеря состояния (см. [[04 key в v-for]]).
- Смена `key` без нужды → полный ремаунт поддерева.
- `v-if` на тяжёлом компоненте, который «мелькает» — лучше `v-show` или `KeepAlive`.

### 4. Шаблон и `computed`

```vue
<!-- ❌ метод вызывается на каждом ререндере -->
{{ formatPrice(total) }}

<!-- ✅ кэш -->
{{ formattedTotal }} <!-- computed -->
```

- `computed` кэширует, метод — нет.
- Тяжёлые фильтры/сортировки — в `computed`, не в шаблоне.

### 5. Пропсы и идентичность

- Передача `reactive` объекта целиком → любое изменение поля «задевает» пропс и родителя.
- Передача примитивов (`id`, `name`) — точечно.
- `v-memo` (3.2+) — ручное кэширование участка шаблона (осторожно).

### 6. Большие данные

- `shallowRef` — если не нужна глубокая реактивность (списки из API).
- `markRaw` — экземпляры классов/сторонние библиотеки.
- **Виртуализация** списков (`vue-virtual-scroller`, `@tanstack/vue-virtual`) — не рендерить тысячи строк.
- `v-for` с `key` — stable.

### 7. KeepAlive/Transition

- Оставленные в кэше компоненты продолжают жить; ограничивайте `include`/`max`.
- Таймеры в `deactivated` не остановлены — «тихие» обновления.

### Как измерять

- **Vue DevTools → Performance** — что рендерится, сколько.
- `onRenderTriggered` — почему компонент обновился (`key`, `oldValue`).
- Chrome Performance — длинные задачи.
- «Highlight updates» в DevTools — визуально видно лишние ререндеры.

### Чек-лист ответа

1. Где живет state (слишком высоко?).
2. Разбиты ли компоненты.
3. `computed` vs методы.
4. Точные `watch`, без `deep` по умолчанию.
5. Стабильные ключи.
6. `shallowRef`/виртуализация для больших данных.
7. Профилирование, а не догадки.

> [!warning] Подвох
> «Почему `watch` на `reactive` объекте не ловит вложенные изменения?» — по умолчанию сравнивается ссылка на объект, а мутация поля меняет объект «на месте»; для вложенных изменений нужен `deep: true` либо getter на конкретное поле (`() => state.a.b`). Для `ref`-объекта то же: `watch(refObj, ...)` сработает на замену `.value`, но не на мутацию вложенного — нужен `deep`.
