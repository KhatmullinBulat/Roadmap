# SSG и prerender

## Краткий ответ (30 секунд)

**SSG** — страницы рендерятся в HTML **на этапе сборки**, результат — статика на CDN. Нет сервера под запрос → дёшево, быстро, надёжно; но данные «замораживаются» на сборке. В Nuxt: `nuxi generate` (или `nuxt generate`), `nitro.prerender`, `routeRules: { "/blog/**": { prerender: true } }`, список маршрутов из CMS/API. Для тысяч страниц — ISR/SWR-режим (`isr: 60`), которые обновляют кэш на сервере, а не на сборке. Выбирают для блогов, документации, лендингов, каталогов, где контент меняется нечасто.

## Подробно

### Когда SSG

- Контент публичный, SEO важен.
- Данные обновляются по расписанию/по вебхуку (CMS публикует → rebuild).
- Нагрузка высокая, бюджет сервера ограничен.
- Лендинги, доки, блог, «страницы города/категории».

### Когда не SSG

- Персонализация, авторизация (кабинет).
- Цены/склад — меняются каждую минуту (SSR/ISR).
- Число страниц огромно и меняется постоянно (медленный build).

### Nuxt

```ts
export default defineNuxtConfig({
  nitro: {
    prerender: {
      routes: ["/", "/sitemap.xml", "/blog/hello"],
      crawlLinks: true,
    },
  },
  routeRules: {
    "/marketing/**": { prerender: true },
    "/catalog/**": { isr: 60 },      // обновлять раз в минуту на сервере
    "/admin/**": { ssr: false },
  },
});
```

- `prerender` — статические файлы.
- `isr` — страница генерируется на первом запросе и кэшируется на N секунд (в Nitro/платформе).
- `swr` — stale-while-revalidate: отдать старое, обновить в фоне.

### Динамические страницы

- Список URL: `nitro.prerender.routes` из API (получить slug списка товаров/статей).
- **Динамические ключи** в `useAsyncData`: ключ должен включать slug, иначе данные «переедут» на соседнюю страницу (частый баг при `crawlLinks`).

### Гидратация и SSG

- HTML статический — гидратация та же, что в SSR.
- Ошибочные данные (время, `Math.random`, глобальный стейт) → **hydration mismatch**.
- `NuxtTime`/`ClientOnly` для клиентских данных.

### CI и инкрементальность

- Build → deploy статики (S3/CDN/IPFS).
- **Вебхуки от CMS** → rebuild/single-page rebuild.
- Для больших сайтов — не «всё каждый раз», а ISR или сегментированный prerender.

### Плюсы/минусы

| | SSG |
|---|---|
| Плюсы | скорость, дешевизна, стабильность, безопасность (нет сервера) |
| Минусы | данные на момент сборки, долгий build, нужен rebuild при контенте |

> [!tip] Как отвечать
> «SSG — статика из сборки: блог, доки, лендинги. Плюсы — скорость и цена, минус — сборка при изменениях. Если данные свежее, то ISR/SWR на сервере. В Nuxt — `nitro.prerender` и `routeRules`».
