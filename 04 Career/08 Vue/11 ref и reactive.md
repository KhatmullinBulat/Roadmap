# ref и reactive

## Краткий ответ (30 секунд)

**`reactive(obj)`** — Proxy над объектом: обращаешься как к обычному объекту (`state.count`), но **нельзя** деструктурировать (`const { count } = state` теряет реактивность), нельзя заменить объект целиком (переменная `reactive` не реактивна), не подходит для примитивов. **`ref(value)`** — универсальная «коробка» `.value`; работает с примитивами и объектами, не теряет реактивность при передаче/деструктуризации (если сохранить сам ref), **можно переприсвоить**. Практика: **`ref` по умолчанию**, `reactive` — для «форм»/сгруппированного состояния внутри компонента, где удобно `state.x`.

## Подробно

### Синтаксис

```js
import { ref, reactive } from "vue";

const count = ref(0);
count.value++;
const double = computed(() => count.value * 2);

const user = reactive({ name: "Аня", age: 20 });
user.name = "Оля";
```

### Ключевые различия

| | `ref` | `reactive` |
|---|---|---|
| Примитивы | ✅ | ❌ |
| `.value` | нужен (кроме шаблонов) | нет |
| Переприсвоить целиком | ✅ `r.value = {...}` | ❌ (меняем поля) |
| Деструктуризация | ✅ (ref сам реактивен) | ❌ (теряется) |
| Передача в функцию | ✅ (ref остаётся реактивным) | ⚠️ Proxy теряется при деструктуризации |
| В шаблоне | автоматически разворачивается | обычный объект |
| Массивы/Map/Set | ✅ | ✅ |
| Классовые инстансы | ✅ (`ref(new C())`) | ⚠️ методы/`this` |
| `typeof` | `object` (не «обёртка для проверок») | `object` |

### Ловушки `reactive`

```js
const state = reactive({ count: 0 });
let { count } = state;          // ❌ копия числа, реактивности нет
const { count: c } = toRefs(state); // ✅ c — ref
state = reactive({});            // ❌ переменная не реактивна
state = { count: 1 };            // ❌ теряется связь
```

- `reactive` в `props` — **не** делать: пропсы уже реактивны, а `reactive(props)` не рекомендуется (документация прямо предупреждает).
- `reactive` не «возвращается» из `setup` как ref — в шаблоне тоже работает (Vue разворачивает).

### Ловушки `ref`

```js
const user = ref({ name: "Аня" });
user.name = "Оля";   // ❌ забыл .value
user.value.name = "Оля"; // ✅
```

- В `<script setup>` — `.value`; в `<template>` — автоматически.
- `ref` в массиве/объекте не разворачивается — нужен `.value`.
- `shallowRef` — для больших данных без глубокой реактивности.
- `ref` можно типизировать: `const el = ref<HTMLInputElement | null>(null)`.

### Когда `reactive` всё-таки лучше

- Форма/настройки: `const form = reactive({ email: "", password: "" })` — много полей, удобнее без `.value`.
- Локальный «мини-стор» в компоненте/композабле.
- Когда нужны `reactive`-коллекции с частыми мутациями.

### Правило команды (и для интервью)

> «По умолчанию `ref`: он предсказуем, переживает передачу и деструктуризацию, работает с примитивами. `reactive` — если это именно объект-состояние и мне удобнее без `.value`; но возвращая наружу, отдаю `toRefs`».

### `toRefs` / `toRef`

```js
const state = reactive({ a: 1, b: 2 });
const { a, b } = toRefs(state); // a/b — refs, синхронны с state
```

Подробнее — [[13 toRefs и деструктуризация]].

> [!warning] Подвох
> «`ref` — это `reactive`?» — `ref` для объектов внутри создаёт `reactive`, но сам — объект с `.value` (и `dep`). Поэтому `isRef(obj)` — true, а `isReactive(ref)` — зависит от значения. Плюс при сравнении `.value` базового объекта и возвращённого из `ref()` — Proxy может дать `!==` (например, `ref(obj).value !== obj`).
