# Глобальные компоненты Vue

## Краткий ответ (30 секунд)

Глобальный компонент регистрируется один раз на приложение — `app.component("AppButton", AppButton)` — и доступен в **любом** шаблоне без импорта. В `<script setup>`/Nuxt чаще используется **локальная** регистрация (автоимпорт компонентов за счёт конвенций) — глобальные хуже для tree-shaking и прозрачности. Оправдано: базовые UI-элементы, используемые почти везде (`AppButton`, `Icon`), и **плагины/библиотеки**, которые регистрируют компоненты при `app.use()` (Element Plus, Vuetify). Не оправдано: единственный компонент на 2 страницах, «чтобы не импортировать».

## Подробно

### Регистрация

```js
// main.js
import { createApp } from "vue";
import App from "./App.vue";
import AppButton from "./components/AppButton.vue";

const app = createApp(App);
app.component("AppButton", AppButton); // глобально
app.mount("#app");
```

```vue
<!-- любой компонент -->
<AppButton>Купить</AppButton>
```

### Typescript: глобальные компоненты и типы

```ts
// components.d.ts
declare module "vue" {
  export interface GlobalComponents {
    AppButton: typeof import("./components/AppButton.vue")["default"];
  }
}
```

Без этого TS в шаблонах не подскажет `AppButton` и будет считать его неизвестным элементом.

### Nuxt: автоимпорт

Nuxt автоматически импортирует компоненты из `components/` (в Nuxt 4 — `app/components/`) с префиксом имени папки. Это **не** глобальная регистрация в рантайме, а компиляционная: компонент подключается там, где использован (treeshaking сохраняется).

```
app/components/base/BaseButton.vue  →  <BaseButton />
```

Можно отключить префикс (`components: { dirs: [...] }`) или добавить `global: true` в `nuxt.config` — тогда компонент будет в глобальном контексте.

### Плюсы и минусы

| | Плюсы | Минусы |
|---|---|---|
| Глобально | короткая разметка, единообразие | бандл: компонент в приложении всегда |
| | плагины и дизайн-системы | трудно найти, где импорт |
| | не нужно писать импорты | конфликт имён, неявная зависимость |
| Локально/автоимпорт | прозрачно, tree-shaking | чуть больше кода |

### Плагины

```js
// plugins/ui.js
import { Button, Modal } from "my-ui-kit";

export default {
  install(app) {
    app.component("UiButton", Button);
    app.component("UiModal", Modal);
  },
};
```

- Так работают Element Plus/Vuetify («всё зарегистрировано»).
- Ленивый вариант — единый компонент `<Ui>` с динамическим `:is` (меньше регистраций, хуже типобезопасность).

### Когда глобальный компонент оправдан

- Единая дизайн-система (`App*`-компоненты) в большом приложении.
- Библиотека/плагин для потребителя.
- Очень базовые элементы (иконки, кнопки) — часто через автоимпорт.

### Когда нет

- Экранная фича, используемая в 1–2 местах.
- Тяжёлые компоненты (редактор, графики) — только лениво ([[08 Асинхронные компоненты]]).
- Компоненты, различающиеся по контексту (лучше локальные/слоты).

> [!tip] Как отвечать
> «Глобально — для дизайн-системы или плагина. В Vue 3/Nuxt предпочитаю автоимпорт компонентов: прозрачно и без потери tree-shaking. Глобальная регистрация тянет всё в бандл и скрывает зависимости».
