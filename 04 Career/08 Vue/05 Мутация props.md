# Почему нельзя мутировать props

## Краткий ответ (30 секунд)

`props` — **входные данные**, принадлежащие родителю, и в **однонаправленном потоке** только родитель их меняет. Если ребёнок мутирует пропс-объект (`props.user.name = "x"`), состояние меняется в обход источника истины: Vue не заметит (для пропсов), состояние рассинхронизируется, а в dev-режиме появится предупреждение о prop mutation. Правильно: 1) **`emit` события** наверх, чтобы изменил родитель; 2) для локальной копии — `const local = ref(props.value)` / `toRefs` (+ `watch` для синхронизации); 3) `v-model` (prop + `update:*`) — форма «согласованной» двусторонней связи.

## Подробно

### Однонаправленный поток

```
Родитель (state) --props--> Ребёнок
Родитель (state) <--emit--- Ребёнок
```

- Пропсы — **readonly** на уровне компонента (для примитивов попытка записи даёт предупреждение; для объектов «пропускает» мутацию, но это ещё хуже).
- Источник истины один — родитель/стор.

```vue
<!-- ❌ -->
<script setup>
const props = defineProps(["user"]);
props.user.name = "Новое"; // мутация объекта, Vue не увидит изменения пропса
</script>

<!-- ✅ -->
<script setup>
const emit = defineEmits(["update:user"]);
defineProps(["user"]);
function rename(name) {
  emit("update:user", { ...props.user, name });
}
</script>
```

### Почему мутация объектов «работает», но неправильно

В Vue 3 реактивность на `Proxy` — `props.user` реактивен, и мутация может «протечь» в родителя (если объект — часть `reactive`-состояния). Это **не** гарантия контракта, а побочный эффект: рефакторинг родителя (замена на новый объект/`toRefs`) ломает ребёнка. Плюс нарушается трассировка изменений (кто и когда поменял).

### Как менять «снизу вверх»

**1. Emit:**

```vue
<!-- Child -->
<button @click="$emit('increment')">+</button>

<!-- Parent -->
<Counter :value="count" @increment="count++" />
```

**2. v-model (по умолчанию `modelValue` + `update:modelValue`):**

```vue
<!-- Child -->
<script setup>
const model = defineModel(); // Vue 3.4+
</script>
<template>
  <input v-model="model" />
</template>
```

**3. Колбэк как проп:**

```vue
<Child :onSave="save" />
```

**4. Shared state** (Pinia/composable) — если данные общие для многих, а не «родитель-ребёнок».

### Когда `props` копировать

- Поле формы, которое редактируется локально, сохраняется по кнопке:

```js
const form = ref({ ...props.initial }); // shallow-копия
watch(() => props.initial, (v) => (form.value = { ...v }));
```

- Глубокая копия — `structuredClone` (осторожно с прокси и функциями).
- `ref` не нужен, если источник — уже `reactive` объект и меняется только через `emit`.

### Антипаттерны

- `props.list.push(x)` — меняет массив родителя.
- `watch(() => props.value, (v) => { props.value = v + 1 })` — цикл/мутация.
- Копирование `ref(props.x)` без синхронизации → расхождение.

> [!tip] Как отвечать
> «Props — вход, менять их — нарушение одностороннего потока. Вверх — `emit` или `v-model`. Для локального редактирования — копия в `ref` и синхронизация через `watch`. Если сложно — значит, состояние живёт не там: поднять выше или в стор».
