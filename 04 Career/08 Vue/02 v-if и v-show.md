# v-if и v-show

## Краткий ответ (30 секунд)

`v-if` **создаёт/разрушает** DOM (ветвления в шаблоне, `v-else`, `v-else-if`) — цена при переключении, но нет узлов в дереве и не выполняются вычисления. `v-show` **всегда рендерит** элемент и переключает `display: none` — дешёвое переключение, но узел остаётся в DOM, компоненты/эффекты живут. Выбор: частое переключение и «визуально скрыть» → `v-show`; редкое переключение, дорогое поддерево без побочных эффектов (или ему нельзя существовать) → `v-if`. Нельзя на одном элементе одновременно, и `v-if` не размещать на том же элементе с `v-for` (приоритеты меняются).

## Подробно

### `v-if`

```vue
<div v-if="status === 'loading'">Загрузка…</div>
<div v-else-if="status === 'error'">Ошибка</div>
<div v-else>Готово</div>
```

- Создание/удаление узлов, вызов `mounted`/`unmounted` дочерних компонентов (**и `onUnmounted`-очисток**).
- Скрытый ветвью компонент теряет **state**.
- При первом `true` — компонент монтируется заново.
- `v-if` на `<template>` — ветвление группы без обёртки.

### `v-show`

```vue
<div v-show="isOpen">Панель</div>
```

- Ставит `style="display: none"`.
- Элемент **остаётся в DOM**: формы сохраняют значения, `KeepAlive` не нужен, но:
  - скрытый `input` всё ещё может получать фокус программно;
  - скрытые изображения/видео могут грузиться;
  - нет `unmounted` — эффекты продолжают работать;
  - accessibility: `display:none` исключает из дерева доступности (это ок), но `aria-hidden` не нужен.
- Не работает на `<template>` (нужен реальный элемент).
- Не работает в некоторых компонентах без `<style display>` — рендерится в корневой узел.

### Когда что

| Сценарий | Выбор |
|---|---|
| Модалка, которая открывается часто | `v-show` (если внутри нет дорогих подписок) |
| Редкий блок «показать справку» | `v-if` |
| Вкладки с тяжёлыми таблицами | `v-if` + `KeepAlive` (сохранить state) |
| Скрытие при ресайзе | `v-if`/CSS |
| Элемент не должен существовать (SEO, побочные эффекты) | `v-if` |
| Частое переключение лёгкого элемента | `v-show` |

### Про `v-if` + `v-for`

```vue
<!-- ❌ до Vue 3 приоритет был у v-for; в Vue 3 у v-if — путаница -->
<li v-for="item in items" v-if="item.visible" :key="item.id">
```

Правильно — отфильтровать в `computed`:

```js
const visibleItems = computed(() => items.value.filter((i) => i.visible));
```

```vue
<li v-for="item in visibleItems" :key="item.id">
```

### Про производительность

- `v-show` экономит создание DOM при частых переключениях.
- `v-if` экономит память и работу скрытых эффектов.
- Для тяжёлых «страниц» — `v-if` + `KeepAlive` + `include`/`exclude`.

> [!warning] Подвох
> «`v-show` выключил таймер внутри?» — нет, компонент не размонтирован, `onUnmounted` не вызовется. На собеседовании это типичное уточнение.
