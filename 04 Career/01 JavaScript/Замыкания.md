# Замыкание

## Краткий ответ (30 секунд)

**Замыкание** — это функция вместе с её *лексическим окружением*: функция «помнит» переменные из места, где её создали, даже если внешняя функция уже завершилась. Переменная живёт, пока на неё есть ссылка из замыкания. На замыканиях построены модули, приватные поля-через-функции, `bind`, обработчики событий, каррирование и счётчики.

## Подробно

```js
function createCounter() {
  let count = 0;
  return {
    increment() { count += 1; },
    get value() { return count; },
  };
}

const counter = createCounter();
counter.increment();
counter.increment();
counter.value; // 2

// count снаружи недоступен — это приватное состояние
counter.count; // undefined
```

### Что именно замыкается

Замыкается **не значение, а сама переменная (binding)**. Если переменная меняется, все функции увидят новое значение:

```js
function makeCounters() {
  const counters = [];
  for (var i = 0; i < 3; i++) {
    counters.push(() => i); // один и тот же var
  }
  return counters.map((fn) => fn());
}
makeCounters(); // [3, 3, 3]

function makeCountersLet() {
  const counters = [];
  for (let i = 0; i < 3; i++) {
    counters.push(() => i); // у let — отдельный binding на итерацию
  }
  return counters.map((fn) => fn());
}
makeCountersLet(); // [0, 1, 2]
```

Классический пример из собеседований: `var` в цикле + `setTimeout` → все колбэки видят последнее значение. С `let` — нет.

### Классический вопрос: приватность

```js
const Counter = (() => {
  let count = 0;
  return {
    inc: () => ++count,
    reset: () => (count = 0),
  };
})();

Counter.inc(); // 1
Counter.count; // undefined
```

`IIFE` создаёт область видимости, которая сохраняется через замыкания. До приватных полей классов (`#count`) и модулей это был стандартный способ инкапсуляции.

### Утечки памяти

Замыкание держит окружение. Если замыкание ссылается на 큰 объект и живёт долго (обработчик на `window`), объект не освободится. Частые утечки:

- обработчик подписан, но не снят (`addEventListener` без `removeEventListener`);
- таймер/интервал не очищен;
- подписка на глобальный стор держится в размонтированном компоненте;
- DOM-узел удалён, но ссылка на него есть в замыкании.

Современный GC умеет освобождать переменные, которые замыкание *не использует*, а не всё окружение целиком — это оптимизация движка, а не гарантия спецификации. Полагаться на неё не стоит.

### Практические места

```js
// 1. Дебаунс
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// 2. Мемоизация
const memo = (fn) => {
  const cache = new Map();
  return (key) => {
    if (!cache.has(key)) cache.set(key, fn(key));
    return cache.get(key);
  };
};

// 3. Каррирование (см. отдельную заметку)
```

> [!tip] Как отвечать
> «Замыкание — это функция и её лексическое окружение. Переменные из внешней функции остаются в памяти, пока на них ссылается замыкание. Поэтому в JavaScript появились модули и классы с `#private`, а не только IIFE. И именно поэтому просто снимайте обработчики и таймеры».
