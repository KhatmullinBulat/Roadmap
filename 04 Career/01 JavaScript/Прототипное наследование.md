# Прототипное наследование

## Краткий ответ (30 секунд)

В JavaScript объекты наследуют свойства по цепочке прототипов. У каждого объекта есть внутренняя ссылка `[[Prototype]]` на другой объект или `null`. При чтении свойства движок сначала ищет его у самого объекта, затем у прототипа, у прототипа прототипа и так до `null`. Классы, `new`, `extends`, `instanceof` — всё это надстройки над этим механизмом. Наследования в смысле C++/Java нет: есть делегирование через ссылку.

## Подробно

### Две разные связи, которые путают

| Что | Где живёт | Что это |
|---|---|---|
| `[[Prototype]]` | внутреннее свойство каждого объекта | Ссылка на объект-прототип *этого* экземпляра |
| `.prototype` | обычное свойство функции (в том числе класса) | Объект, который станет `[[Prototype]]` экземпляров, созданных через `new` |

```js
function User(name) {
  this.name = name;
}
User.prototype.greet = function () { return `Привет, ${this.name}`; };

const user = new User("Булат");

Object.getPrototypeOf(user) === User.prototype; // true
Object.getPrototypeOf(User.prototype) === Object.prototype; // true
Object.getPrototypeOf(Object.prototype); // null — конец цепочки

// НО: User сам по себе — функция, и её [[Prototype]] — Function.prototype
Object.getPrototypeOf(User) === Function.prototype; // true
```

### Что делает `new`

1. создаёт новый пустой объект;
2. ставит ему `[[Prototype]] = Fn.prototype`;
3. вызывает `Fn` с `this`, равным этому объекту;
4. если функция вернула объект — возвращает его, иначе вернёт созданный.

JavaScript-функции, которые используются как конструкторы, ведут себя именно так; `new.target` позволяет понять, вызвали ли функцию через `new`.

### Цепочка чтения и записи

- **Чтение** идёт вверх по цепочке до первого найденного свойства.
- **Запись** `obj.x = 1` создаёт *собственное* свойство. Оно **затеняет** («shadowing») унаследованное, но не меняет его.
- Исключение: если в прототипе есть *сеттер* для `x`, присваивание вызовет его.
- `delete obj.x` удаляет только собственное свойство.

```js
const defaults = { theme: "light" };
const settings = Object.create(defaults);

settings.theme;          // "light"
settings.theme = "dark"; // создаёт собственное свойство
defaults.theme;          // "light" — прототип не изменился
```

### Классы — синтаксический сахар

```js
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} издаёт звук`; }
}

class Dog extends Animal {
  speak() { return `${super.speak()} — гав`; }
}

Object.getPrototypeOf(Dog.prototype) === Animal.prototype; // true
Object.getPrototypeOf(Dog) === Animal;                     // true (статическое наследование)
```

`super` — не свойство объекта, а особый синтаксис, который ищет метод в прототипе родителя. Методы класса лежат в `Dog.prototype` и не копируются в каждый экземпляр.

### Прототип без прототипа

`Object.create(null)` создаёт объект без `toString`, `hasOwnProperty` и `__proto__`. Удобен как словарь с произвольными ключами (безопаснее против prototype pollution).

### Как менять прототип

- Создавать сразу с нужным прототипом: `Object.create(proto)`.
- Для классов можно явно выставить prototype до создания экземпляров (например, на этапе определения класса).
- `Object.setPrototypeOf()` работает, но движок не сможет оптимизировать объекты без обновления; менять прототип уже «живого» объекта — антипаттерн, о котором можно сказать на собеседовании, отвечая на вопрос про производительность.

### Что спрашивают дальше

- Почему методы кладут в `prototype`: чтобы они не дублировались в каждом экземпляре (экономия памяти).
- Что вернёт `obj.hasOwnProperty("x")`, если ключ в прототипе — `false` (если у объекта вообще есть `hasOwnProperty`).
- `obj instanceof Ctor` проходит всю цепочку в поисках `Ctor.prototype`.
- Как реализовать «наследование» без классов: `Child.prototype = Object.create(Parent.prototype); Child.prototype.constructor = Child;`.
