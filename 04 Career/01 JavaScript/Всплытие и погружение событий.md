# Всплытие, погружение, делегирование

## Краткий ответ (30 секунд)

Событие в DOM проходит три фазы: **погружение** (capture, от `window` вниз к цели), **цель** (target) и **всплытие** (bubble, от цели вверх к `window`). Обработчик без опций срабатывает в фазе всплытия; `{ capture: true }` — в фазе погружения. **Делегирование** — один обработчик на общем контейнере вместо обработчика на каждом дочернем элементе; работает за счёт всплытия (или погружения) и `event.target`.

## Подробно

### Фазы

```js
// Погружение: window → document → html → body → … → container → target
// Цель:       сами обработчики на target
// Всплытие:   target → … → container → body → html → document → window
```

Три фазы описал W3C в DOM Level 2 Events; фаза «цель» формально не считается ни погружением, ни всплытием, но в спецификации имеется в виду, что на самом `event.target` срабатывают все обработчики в порядке добавления (capture-обработчики раньше обычных).

```html
<div class="outer" style="padding: 20px; background: #eee">
  <button class="inner">Кнопка</button>
</div>
<script>
  document.querySelector(".outer").addEventListener("click", () => console.log("bubble outer"));
  document.querySelector(".outer").addEventListener("click", () => console.log("capture outer"), true);
  document.querySelector(".inner").addEventListener("click", () => console.log("target/button"));
</script>
```

Порядок логов: `capture outer` → `target/button` → `bubble outer`.

### Что ещё важно знать

- **`addEventListener(type, fn, options)`** — третий аргумент может быть объектом: `{ capture, once, passive, signal }`. `once: true` снимает обработчик после первого вызова, `signal` позволяет снять его через `AbortController`.
- **`stopPropagation()`** останавливает движение события, но обработчики *на том же элементе* ещё выполнятся. **`stopImmediatePropagation()`** останавливает и их.
- **`preventDefault()`** отменяет действие по умолчанию (переход по ссылке, отправку формы), а не всплытие. Это две независимые оси.
- Всплывают не все события: `focus`, `blur`, `mouseenter`, `mouseleave`, `load` не всплывают (есть `focusin`/`focusout`, `mouseover`/`mouseout` — они всплывают).
- Некоторым событиям нужно `{ passive: true }`, чтобы браузер не ждал JavaScript и не блокировал скролл: `touchstart`, `touchmove`, `wheel`. Если вызвать `preventDefault()` в passive-обработчике, браузер только выдаст предупреждение в консоль.

### Делегирование

Вместо N обработчиков — один на контейнере:

```js
const list = document.querySelector(".list");

list.addEventListener("click", (event) => {
  const item = event.target.closest("[data-id]");
  if (!item || !list.contains(item)) return; // клик не по элементу списка
  console.log("выбран", item.dataset.id);
});
```

**Плюсы:** меньше обработчиков (меньше памяти и времени подписки), работает для динамически добавляемых элементов, один обработчик проще обновлять.
**Минусы:** нужно поднимать `event.target` до нужного элемента (`closest`), часть событий не всплывает, при делегировании «всё через один обработчик» проще ошибиться с селектором и возникает лишняя «прослойка». Делегирование не стоит применять к событиям на самой странице (`document`), если их много и они частые, — лучше на конкретный контейнер.

Пример `closure` здесь работает: `event` приходит в аргументе, а не из общей переменной, поэтому обработчик не мешает между вызовами.

> [!tip] Ответ экзаменатору
> «Погружение вниз, всплытие вверх — я обычно работаю со всплытием. Делегирование использую, например, для списков с тысячей строк: один слушатель на `<tbody>` плюс `closest`, чтобы понимать, на каком ряду кликнули. Если нужен отлов клика до дочерних обработчиков — capture, если хочу отловить клик вне компонента — capture на `document`».

## Быстрая шпаргалка

| Что | Ответ |
|---|---|
| Порядок фаз | capture → target → bubble |
| Обработчик на target | Сначала добавленные в capture-фазе, затем обычные |
| Отменить всплывание | `stopPropagation()` |
| Отменить действие | `preventDefault()` |
| Не всплывают | `focus`, `blur`, `mouseenter`, `load` |
| Делегирование | Один слушатель на контейнере + `event.target.closest()` |
| Passive | `{ passive: true }` для `scroll`-подобных событий |

## Термины

- **Event propagation** — путь события по дереву DOM.
- **Event delegation** — переиспользование одного обработчика для группы дочерних узлов.
- **event.target** — элемент, который реально получил событие.
- **event.currentTarget** — элемент, на котором сработал обработчик.
