# Способы клонировать объект

## Краткий ответ (30 секунд)

Поверхностная копия (`{...obj}`, `Object.assign`) копирует только первый уровень: вложенные объекты остаются теми же ссылками. Глубокая копия (`structuredClone`, библиотечный `_.cloneDeep`) копирует вложенные структуры рекурсивно. `JSON.parse(JSON.stringify())` выглядит как глубокая копия, но теряет `undefined`, функции, `Date` (превращается в строку), `Map`, `Set`, `RegExp`, `BigInt` и циклические ссылки. Для объектов с методами/классовыми экземплярами универсального «клона» нет — копируйте явно через конструктор или метод `clone()`.

## Подробно

### 1. Поверхностное копирование

```js
const source = { a: 1, nested: { b: 2 } };

const spread = { ...source };
const assigned = Object.assign({}, source);

spread.nested.b = 99;
console.log(source.nested.b); // 99 — вложенный объект общий
```

- `{...src}` — объектный spread (ES2018), вычисляет геттеры и копирует как значения.
- `Object.assign({}, src)` делает то же самое; оба варианта копируют и ключи-`Symbol`.
- **Плюсы:** быстро, читаемо.
- **Минусы:** вложенность и прототип не копируются (spread всегда даёт объект с `Object.prototype`; `Object.assign` берёт метод только если у `target` свой прототип).

Для массивов: `[...arr]`, `arr.slice()`, `Array.from(arr)` — тоже поверхностные.

### 2. `structuredClone()`

Встроенный с 2022 (Baseline), самый удобный вариант для данных:

```js
const source = { a: 1, d: new Date(), set: new Set([1, 2]), nested: { x: 1 } };
const clone = structuredClone(source);

clone.nested.x = 5;
console.log(source.nested.x); // 1 — копия глубокая
```

- **Поддерживает:** `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`/TypedArray, `Blob`, `File`, `ImageData`, `Error`, циклические ссылки, `undefined`.
- **Не поддерживает:** функции, DOM-узлы, Promise, WeakMap/WeakSet, классовые экземпляры (получится обычный объект с теми же свойствами, без прототипа), геттеры/сеттеры (свойства станут обычными).
- **Кидает `DataCloneError`**, если встретил неподдерживаемое значение.

### 3. `JSON.parse(JSON.stringify(obj))`

Классика, которую часто спрашивают именно для проверки знания ограничений:

| Значение | Что станет |
|---|---|
| `undefined` (в объекте) | свойство исчезнет |
| `undefined` (в массиве) | `null` |
| `Date` | строка ISO |
| `NaN`, `Infinity` | `null` |
| `Map`/`Set` | `{}` |
| функция, `Symbol` | свойство исчезнет |
| `BigInt` | `TypeError` |
| циклическая ссылка | `TypeError` |

**Плюсы:** одна строка, не нужны зависимости (исторически). **Минусы:** список выше; для данных, где это не важно (плейн JSON) — нормально, для состояния приложения — опасно.

### 4. Ручной глубокий клон / библиотеки

`lodash.clonedeep`, `rfdc`, `klona` поддерживают больше типов, сохраняют прототипы и корректно обходят циклы. Стоит выбирать, если нужен контроль над `Map`, классами, символами.

```js
const clone = structuredClone(source);     // современный стандарт
const clone2 = _.cloneDeep(source);        // если нужны классы
```

### 5. Иммутаберсные техники

Если задача — «изменить вложенное свойство, не мутируя исходник», не обязательно клонировать целиком:
- `{ ...state, user: { ...state.user, name: "Анна" } }` — копируем только путь к изменению;
- `immer` — `produce(state, draft => { draft.user.name = "Анна" })` — пишет «мутабельно», результат получает неизменяемым благодаря `Proxy`/копированию path;
- `toSorted`, `toReversed`, `toSpliced`, `with` — новые немутирующие методы массивов (ES2023).

## Сравнение

| Способ | Глубина | Циклы | Date / Map / Set | Функции | Прототип |
|---|---|---|---|---|---|
| `{...obj}` | поверхностная | да (общие ссылки) | нет (ссылки) | ссылка | теряется |
| `Object.assign` | поверхностная | да | нет | ссылка | по `target` |
| `structuredClone` | глубокая | да | да | не поддерживает | теряется |
| JSON | глубокая | падает | теряет | теряет | теряется |
| `_.cloneDeep` | глубокая | да | да | ссылка | сохраняет |
| `immer` | ленивая (copy-on-write) | — | да | да | зависит |

## Термины

- **Shallow copy** — копия только верхнего уровня; вложенные значения по ссылке.
- **Deep copy** — рекурсивная копия; вложенные объекты — новые.
- **Structural sharing** — при «неизменяемом» обновлении общие части остаются по ссылке.
