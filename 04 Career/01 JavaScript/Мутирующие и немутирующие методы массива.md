# Мутирующие и немутирующие методы массива

## Краткий ответ (30 секунд)

Мутирующие методы меняют исходный массив на месте: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`, `copyWithin`. Немутирующие возвращают новый массив или другое значение и не трогают оригинал: `map`, `filter`, `slice`, `concat`, `flat`, `flatMap`, `toSorted`, `toReversed`, `toSpliced`, `with`, а также методы поиска (`find`, `some`, `every`, `includes`, `indexOf`, `reduce`, `forEach`). Для иммутабельного кода намеренно используют `toSorted`/`toReversed`/`toSpliced`/`with` вместо `sort`/`reverse`/`splice`.

## Подробно

### Мутирующие

| Метод | Что делает |
|---|---|
| `push` / `pop` | добавляет / убирает элемент в конце |
| `unshift` / `shift` | добавляет / убирает элемент в начале |
| `splice(start, deleteCount, ...items)` | удаляет/вставляет; **возвращает удалённые элементы**, меняя оригинал |
| `sort(cmp)` | сортирует (по умолчанию — как строки!) |
| `reverse()` | разворачивает на месте |
| `fill(value, start, end)` | заполняет диапазон |
| `copyWithin(target, start, end)` | копирует часть в другую позицию того же массива |

```js
const a = [3, 1, 2];
a.sort();        // по умолчанию ["1","2","3"] как строк
a.sort((x, y) => x - y); // числа: [1, 2, 3]
```

### Немутирующие: возвращают новый массив

`map`, `filter`, `slice`, `concat`, `flat`, `flatMap`, `toSorted`, `toReversed`, `toSpliced`, `with` (ES2023).

```js
const source = [3, 1, 2];

const sorted = source.toSorted();   // [1, 2, 3]
source;                              // [3, 1, 2]

const replaced = source.with(0, 10); // [10, 1, 2]
```

### Немутирующие: возвращают другое значение

`find`, `findIndex`, `findLast`, `some`, `every`, `includes`, `indexOf`, `lastIndexOf`, `join`, `reduce`, `forEach` (возвращает `undefined`).

```js
const users = [{ id: 1 }, { id: 2 }];
const u = users.find((x) => x.id === 2); // сам объект, не копия!
```

> [!warning] Подвох на собеседовании
> «Немутирующий» метод не копирует элементы глубоко. `filter`/`map` возвращают новые массивы, но объекты внутри — те же ссылки. Изменив `users[0].name` после `filter`, вы измените объект «в исходном» массиве тоже. Методы немутирующие, а данные — нет.

### Новые методы (ES2023)

`toSorted`, `toReversed`, `toSpliced`, `with` — появились, чтобы не мутировать состояние (например, в React/Redux), не делая вручную `[...arr].sort()`. `reverse` и `sort` остались мутирующими для обратной совместимости.

### Как быстро проверить

- `Array.prototype` — есть `toSorted`/`with` → ES2023+.
- Проверьте на практике: `const b = a.map(x => x); a === b // false`.

### Паттерны из интервью

*Изменить один элемент без мутации:*
```js
const next = list.with(index, { ...list[index], done: true });
```

*Удалить элемент без мутации:*
```js
const next = list.filter((_, i) => i !== index);
// или
const next = [...list.slice(0, i), ...list.slice(i + 1)];
```

*Отсортировать копию:*
```js
const sorted = [...list].sort((a, b) => a.order - b.order);
```

### Производительность

Мутирующие методы в среднем быстрее: не создают новый массив. `splice` и `unshift` в начале массива — O(n) из-за сдвига. `sort` — O(n log n), `map`/`filter` — O(n). Если важна неизменяемость — используйте копии осознанно, а не «на всякий случай».
