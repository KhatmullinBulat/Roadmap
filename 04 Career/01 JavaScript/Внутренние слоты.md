# Внутренние слоты `[[ ]]` в спецификации

## Краткий ответ (30 секунд)

`[[ ] ]` в спецификации ECMAScript — это **внутренние слоты и внутренние методы**: невидимые из JavaScript поля и операции, которые спецификация определяет у каждого объекта. Например, `[[Prototype]]` — ссылка на прототип, `[[Get]]`/`[[Set]]` — операции чтения и записи (их переопределяют Proxy), `[[PromiseState]]`/`[[PromiseResult]]` — состояние промиса, `[[Call]]` — «это можно вызвать». Они не доступны как обычные свойства: их нельзя прочитать через точку, они не перечисляются и не проходят через `getOwnPropertyNames`. Часть из них (или их эффект) доступна через стандартные API — `Object.getPrototypeOf`, `typeof`, `Promise.prototype.then`.

## Подробно

### Зачем существуют слоты

Спецификация описывает объекты JavaScript на уровне внутренних операций. `[[ ]]` — алгебраические нотации спецификации: так записывают поля реализации, которые не должны быть видны в коде, или операции над объектом. JS-движки реализуют их так, как им удобно (V8 — маппдинги свойств в C++ структурах).

### Основные слоты, которые спрашивают

| Слот | Где | Что значит |
|---|---|---|
| `[[Prototype]]` | каждый объект | прототип; читается через `Object.getPrototypeOf` |
| `[[Extensible]]` | каждый объект | можно ли добавлять новые свойства |
| `[[PrivateMethods]]`/`[[PrivateFields]]` | классы | приватные поля `#x` |
| `[[Get]]`, `[[Set]]`, `[[HasProperty]]`, `[[Delete]]` | объект | операции доступа; их *переопределяет* `Proxy` |
| `[[Call]]` | вызываемые объекты | «можно ли вызвать как функцию» |
| `[[Construct]]` | конструкторы | «можно ли вызвать через `new`» |
| `[[PromiseState]]`, `[[PromiseResult]]` | Promise | внутреннее состояние промиса |
| `[[HomeObject]]` | методы классов | где лежит метод — чтобы `super` знал, откуда искать |
| `[[BoundThis]]`, `[[BoundArgs]]` | результат `bind` | что за this и аргументы скопированы |
| `[[RegexpMatcher]]`, `[[OriginalSource]]` | RegExp | состояние регулярки |

### Как это ощущается в коде

```js
const obj = {};
Object.getPrototypeOf(obj); // [[Prototype]] — доступен через API
obj["[[Prototype]]"];       // undefined — обычная строка не даст слот
```

Обращение к `[[PromiseState]]` невозможно: состояние промиса не читается ни одним стандартным свойством. Именно поэтому промис нельзя «синхронно узнать»: он всегда нужен через `then`/`await`.

`typeof` для функции `=== "function"` — это фактически проверка `[[Call]]` (а для классов — `[[Construct]]` есть, `[[Call]]` есть только у конструкторов с `super`, но без `new` класс бросит `TypeError`).

### Внутренние методы и Proxy

`Proxy` перехватывает внутренние методы: хендлер `get` — это переопределение `[[Get]]`, `has` — `[[HasProperty]]`, `ownKeys` — `[[OwnPropertyKeys]]`, `getPrototypeOf` — доступ к `[[Prototype]]`. Это популярный «правильный» ответ на вопрос «почему Proxy может перехватить всё».

### Инварианты

Спецификация накладывает на слоты инварианты: например, если `[[Extensible]]` — `false`, `Proxy` не может соврать и добавить свойства через `ownKeys`. Инварианты нужны, чтобы «проксировать» объект не ломало фундаментальные ожидания языка.

> [!tip] Как отвечать
> «`[[ ]]` — это не синтаксис JavaScript, а нотация внутренних слотов в спецификации ECMAScript. В коде их не прочитать напрямую, но часть из них видна через стандартные функции — `Object.getPrototypeOf` для `[[Prototype]]`, `Promise` методы для `[[PromiseState]]` — а Proxy перехватывает внутренние операции вроде `[[Get]]` и `[[HasProperty]]`».
