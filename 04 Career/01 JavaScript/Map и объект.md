# Map и объект

## Краткий ответ (30 секунд)

`Object` — это структура с прототипом, где ключи в основном строки (плюс `Symbol`); `Map` — специализированная коллекция ключ-значение с **любыми** ключами (объекты, функции, `NaN`), **порядком вставки** при итерации и размером `size`. `Map` быстрее на частых добавлениях/удалениях, у него есть `has`/`delete`/`clear`, нет наследования от `Object.prototype`, и он не подвержен коллизиям со служебными ключами (`__proto__`, `toString`).

## Подробно

Объект `{}` — это по сути хэш-таблица, но с историческим «наследством»: прототип, `constructor`, `toString`, ключи-строки.

### Сравнение

| Критерий | `Map` | `Object` |
|---|---|---|
| Тип ключей | любые, включая объекты и `NaN` | строки и `Symbol` |
| Порядок | порядок вставки | сложный: строковые ключи в порядке вставки, integer-подобные — по возрастанию |
| Размер | `map.size` (O(1)) | `Object.keys(obj).length` (O(n)) |
| Итерация | встроенная, `Symbol.iterator` | `Object.entries`/`for...in` (нужно `hasOwn`) |
| Прототип | нет (чистая коллекция) | `Object.prototype` (ключи `toString`, `__proto__` — коллизии) |
| Безопасность от pollution | да | нужен `Object.create(null)` |
| Производительность | хорошая на add/delete | хорошая на «статический» доступ |
| JSON | `JSON.stringify(map)` → `{}` | нативно |
| Сериализация | вручную | нативно |
| Простой доступ | `map.get(key)` | `obj.key` (быстрее и короче) |

### Когда что

- **`Object`** — фиксированный набор полей с известным типом (`User = { id, name }`), удобство `.`, сериализация в JSON, деструктуризация.
- **`Map`** — динамический словарь, ключи извне, много удалений, ключи-объекты, подсчёт частот, кэш.
- **`Map` в качестве LRU-кэша** — благодаря порядку вставки и `map.keys().next()` удалять самый старый ключ.

```js
const cache = new Map();
cache.set("a", 1).set("b", 2);

cache.has("a"); // true
for (const [k, v] of cache) { ... }
cache.size;     // 2
```

### Важные отличия, которые спрашивают

1. **Ключи:** `obj[1]` и `obj["1"]` — один и тот же ключ. `map.set(1, ...)` и `map.set("1", ...)` — разные.
2. **`NaN`:** в `Map` работает как ключ, а в объекте `obj[NaN]` превращается в `"NaN"`.
3. **`Object.fromEntries(map)`** и `new Map(Object.entries(obj))` — преображения.
4. **`Object.keys` берёт не всё:** только собственные перечисляемые; `for...in` залезает в прототип.
5. **`Object.create(null)`** решает проблемы `__proto__`, но теряет все методы.

### Map-производные

- **`WeakMap`** — ключи только объекты, и они слабые (см. [[WeakMap и WeakSet]]).
- **`Set`** — множество уникальных значений, та же логика; `new Set(arr)` для дедупликации.

### Производительность

- У `Map` операции `set/get/has/delete` в среднем O(1) — и для больших объёмов это стабильнее, чем объект (который в V8 имеет скрытые классы).
- Частое добавление/удаление ключей: `Map` существенно быстрее, потому что объект меняет «shape» и уходит в dictionary mode.
- Для `Object` частые `delete` — антипаттерн: `delete` меняет скрытый класс и часто переводит объект в медленный режим.
