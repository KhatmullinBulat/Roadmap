# Где хранить данные на фронтенде

## Краткий ответ (30 секунд)

В браузере: **`localStorage`** (синхронный, ~5–10 МБ, строки, живёт до очистки), **`sessionStorage`** (та же API, живёт до закрытия вкладки), **`IndexedDB`** (асинхронная объектная БД, сотни МБ, сложные данные), **`Cache Storage`** (HTTP-ответы для Service Worker), **`cookies`** (для сервера, максимум ~4 КБ, шлются автоматически), а также **`OPFS`** (файлы), `window.name`/`history.state` (для истории), `Memory` (в JS-переменных). Выбор зависит от размера, синхронности, жизненного цикла и того, нужны ли данные серверу.

## Подробно

### Сравнение

| Хранилище | Объём | API | Срок жизни | Запросы сервера | Тип данных |
|---|---|---|---|---|---|
| `localStorage` | 5–10 МБ | синхронный | до очистки пользователем | нет | строки |
| `sessionStorage` | 5–10 МБ | синхронный | до закрытия вкладки | нет | строки |
| `IndexedDB` | сотни МБ / квота диска | асинхронный | до очистки | нет | любые (structured clone) |
| `CacheStorage` | большой | асинхронный | до очистки | нет | `Request`/`Response` |
| Cookie | ~4 КБ | синхронный | по `Max-Age` | **да, автоматически** | строка |
| OPFS (File System) | большой | асинхронный | до очистки | нет | файлы |
| `history.state` | маленький | синхронный | для записи истории | нет | structured clone |

### localStorage

```js
localStorage.setItem("theme", "dark");
localStorage.getItem("theme");
localStorage.removeItem("theme");
```

- **Синхронный** — блокирует поток; нельзя хранить много.
- **Строки**: `JSON.stringify`/`parse` вручную.
- **Приватный режим** может бросать `QuotaExceededError` (Safari исторически).
- **Общий** для всех вкладок и вкладок с одним origin; событие `storage` о синхронизации.
- Не хранить токены, если важна XSS-защита.

### sessionStorage

То же API, срок жизни — **вкладка/сессия**. Удобно для многошаговых мастеров и черновиков форм. При «Duplicate tab» копируется.

### IndexedDB

```js
const db = await new Promise((resolve, reject) => {
  const req = indexedDB.open("app", 1);
  req.onupgradeneeded = () => req.result.createObjectStore("notes", { keyPath: "id" });
  req.onsuccess = () => resolve(req.result);
  req.onerror = () => reject(req.error);
});

await new Promise((resolve) => {
  const tx = db.transaction("notes", "readwrite");
  tx.objectStore("notes").put({ id: 1, text: "…" });
  tx.oncomplete = resolve;
});
```

- Хранит объекты, `Blob`, `File`, массивы — через structured clone.
- Транзакции, индексы, курсоры, `keyPath`, `autoIncrement`.
- Асинхронный, работает в worker.
- Обычно оборачивают через `idb`/`dexie`. 
- Браузер может **очистить** при нехватке места (кроме «persistent storage» — `navigator.storage.persist()`).

### CacheStorage

```js
await caches.open("v1").then((cache) => cache.addAll(["/", "/app.js"]));
```

Используется Service Worker для офлайн-режима (PWA). Это не «данные приложения», а HTTP-ресурсы.

### Cookies

Только если данные нужны серверу (сессия, CSRF-токен). Синхронный доступ, уходят с каждым запросом. См. [[Cookies и флаги]].

### Взгляд по сценариям

- **Настройки** (тема, язык) → `localStorage`.
- **Кэш данных списков** с офлайн → `IndexedDB` (+ кэш через SW).
- **Черновик формы** → `sessionStorage` (при закрытии вкладки не нужен).
- **Токен сессии** → `HttpOnly` cookie.
- **Большие файлы** → OPFS или `IndexedDB` (Blob), либо в файловую систему через FileSystem Access API.
- **Временное состояние** → переменные в памяти + контексты.

### Сводка предостережений

- Все эти хранилища **на уровне origin**: нельзя читать чужой origin; XSS даёт доступ ко всем, кроме `HttpOnly` cookie.
- Квота и вытеснение: браузер может удалить данные при малом месте. Для важных данных — `navigator.storage.persist()` (не всегда выдаётся).
- Нет гарантий синхронизации между устройствами (кроме своей синхронизации).

> [!tip] Как отвечать
> «localStorage — маленький синхронный кэш строк. IndexedDB — большие объекты и офлайн. Cookies — когда данные нужны серверу, но до 4 КБ. CacheStorage — ресурсы для Service Worker. Токены — в HttpOnly cookie, а не в localStorage».
