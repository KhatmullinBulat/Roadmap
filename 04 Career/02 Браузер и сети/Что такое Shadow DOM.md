# Что такое Shadow DOM

## Краткий ответ (30 секунд)

**Shadow DOM** — механизм инкапсуляции DOM и стилей: у элемента есть собственное «теневое» дерево, отделённое от основного документа. Стили снаружи не пробивают границу, стили внутри не «утекают» наружу (за исключением наследуемых свойств и CSS-переменных), а селекторы документа не видят элементы внутри. Основа **Web Components** вместе с `<template>`, кастомными элементами и `slot`. Используется в родных элементах (`<input type="range">`, `<video>`), в дизайн-системах, и в изолированных виджетах/расширениях.

## Подробно

### Создание

```js
class FancyButton extends HTMLElement {
  constructor() {
    super();
    const shadow = this.attachShadow({ mode: "open" });
    shadow.innerHTML = `
      <style>
        button { background: hotpink; color: white; border: 0; padding: 8px 16px; }
      </style>
      <button><slot></slot></button>
    `;
  }
}
customElements.define("fancy-button", FancyButton);
```

```html
<fancy-button>Купить</fancy-button>
```

### Ключевые понятия

- **Shadow root**: корень теневого дерева (`mode: "open"` — доступен через `element.shadowRoot`; `"closed"` — нет).
- **Shadow host**: элемент, к которому прикреплён shadow root.
- **`<slot>`**: точка, куда попадает контент из «светлого» DOM (light DOM).
- **Slotted content**: переданные дети хоста; они остаются в обычном DOM, но отображаются внутри.
- **`:host`** — селектор для самого хоста; **`::part()`** — для стилизации внутренних частей снаружи (если элемент это разрешил); **`::slotted()`** — для переданного контента.
- **`:host-context(...)`** — стили, зависящие от контекста (устаревает / не во всех браузерах).

### Инкапсуляция: что именно изолировано

- **Селекторы**: `document.querySelectorAll("button")` не видит кнопки внутри shadow root. Нужно `el.shadowRoot.querySelector(...)` (при `open`).
- **Стили**: `body button { ... }` не влияет на shadow DOM.
- **Наследование**: `color`, `font-family`, `line-height` **наследуются** через границу — это осознанно.
- **CSS-переменные** пробивают границу (удобно для темизации).
- **События**: большинство событий всплывают из shadow DOM наружу, но `event.target` **ретаргетится** до хоста (composed events). `event.composedPath()` показывает настоящий путь.
- **Исключение — `mode: "closed"`**: снаружи `shadowRoot` не получить, но это не защита от JS внутри.

### Зачем использовать

1. **Инкапсуляция компонентов дизайн-системы** — стили не «протекают» и не конфликтуют с хост-приложением.
2. **Виджеты и embed-ы** — чат, поддержка, плеер из другого приложения.
3. **Родные элементы** — уже внутри используют shadow DOM.
4. **Расширения браузера** — UI не ломает стили страницы.

### Минусы

- Сложнее с e2e/юнит-тестами (`shadowRoot`).
- **Стилизация снаружи ограничена** (`::part`, переменные), иногда это мешает.
- React/Vue не всегда «дружат» с теневой инкапсуляцией: обёртки, события ретаргетятся.
- Стоимость: вложенные shadow roots могут влиять на производительность стилей (при очень большом количестве).
- Доступность: нужно правильно строить ARIA внутри; скринридеры видят всё вместе.
- SEO: контент внутри shadow DOM индексируется, но эвристики простых краулеров могут его не «понять».

### Связь с Web Components

`Custom Elements` (регистрация тега) + `Shadow DOM` (инкапсуляция) + `<template>`/`<slot>` (разметка) = **Web Components**. Разговорный «Shadow DOM» — одна из трёх частей.

> [!tip] Как отвечать
> «Shadow DOM — это отдельное дерево внутри элемента, где стили и селекторы изолированы. Наружу можно влиять только через CSS-переменные, `::part` и хост. События всплывают, но `target` ретаргетится до хоста. Используется в Web Components и виджетах».
