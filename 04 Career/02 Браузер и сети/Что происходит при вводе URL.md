# Что происходит при вводе URL в адресную строку

## Краткий ответ (30 секунд)

Браузер: 1) разбирает URL и решает — поиск или адрес; 2) находит IP через **DNS** (сначала кэш ОС/браузера, затем рекурсивный DNS); 3) устанавливает **TCP**-соединение, при HTTPS — **TLS**-рукопожатие (SNI, сертификат, ключи); 4) отправляет **HTTP**-запрос; 5) получает ответ, разбирает HTML, строит **DOM**, загружает ресурсы, **CSSOM**, затем **layout/paint**; 6) выполняет **JS**, рендерит. Ключевые компоненты браузера: UI-поток, сетевой поток, потоки рендерера, GPU.

## Подробно

### 1. URL → запрос

- Адресная строка распознаёт схему (`https:`), хост (`example.com`), путь, query, фрагмент.
- Если это похоже на поисковую фразу — уходит в поисковик.
- **HSTS** может принудительно переписать `http` → `https` до отправки.
- Браузер проверяет кэш HTTP (по заголовкам), кэш DNS, предзагрузку (`preconnect`/`dns-prefetch`).

### 2. DNS

```
кэш браузера → кэш ОС → hosts-файл → resolver (провайдер) → корневые/TLD/authoritative серверы
```

- Рекурсивный резолвер спрашивает корневые серверы (`.`), затем серверы зоны (`.com`), затем NS домена.
- Результат — `A`/`AAAA` (IPv4/IPv6) или `CNAME`.
- Часто дополнительно: `TXT`, `MX`, `HTTPS`-записи.

### 3. TCP + TLS

- **TCP-хендшейк** (SYN → SYN-ACK → ACK), затем отправка.
- **TLS 1.3**: ClientHello (приветствие, поддерживаемые cipher suites, SNI) → ServerHello + сертификат → проверка цепочки → обмен ключами → шифрованный канал. TLS 1.3 — 1-RTT (2-RTT всего с TCP) вместо 3-TLS 1.2.
- Для повторного соединения — **session resumption** / 0-RTT.

### 4. HTTP-запрос и ответ

- Заголовки: `Host`, `User-Agent`, `Accept`, `Cookie`, `Cache-Control` и т.д.
- Ответ: статус, заголовки (`Content-Type`, `Content-Encoding`, `Cache-Control`), тело.
- **HTTP/2/3** мультиплексируют потоки в одном соединении; HTTP/3 — поверх QUIC/UDP.

### 5. Обработка ответа

- Браузер смотрит `Content-Type`, декодирует (gzip/brotli), выполняет **preload scanner** — он находит `<link>`, `<script>`, `<img>` и запускает загрузку заранее.
- HTML парсится в **DOM**; CSS — в **CSSOM**. Внешние стили блокируют отрисовку, `display: none` — просто исключает из рендера.
- `script` без `defer`/`async` блокирует парсер.
- **Layout → Paint → Composite** (см. [[Рендер layout paint compositing]]).

### 6. Рендер

- Первая отрисовка → `First Contentful Paint`, крупные элементы → `LCP`.
- Затем JS (React и т.п.), события, анимации.

## Что подчеркнуть на собеседовании

- Это не «один процесс»: браузер разбит на потоки/процессы (UI, сеть, рендерер, GPU). Это изолирует вкладки и повышает безопасность.
- HTTPS уже на стадии соединения: клиент не отправляет приложение раньше TLS.
- Кэширование и DNS влияют на скорость сильнее, чем сам HTTP (Lighthouse ругается на «нет кэша»).
- Порядок «DNS → TCP → TLS → HTTP → parse → render» — то, что ждут в ответе.

> [!tip] Коротко
> «URL → DNS → TCP+TLS → HTTP → HTML → DOM/CSSOM → layout/paint. Плюс кэши браузера, ОС и DNS и предзагрузка сканера».
