# Моки, стабы и фейки

## Краткий ответ (30 секунд)

- **Stub** — подменённый ответ (вернуть 42).
- **Spy** — обёртка, которая записывает вызовы (`vi.spyOn`) и может остаться настоящей реализацией.
- **Mock** — и spy, и stub: записывает вызовы и возвращает запрограммированное поведение (`vi.fn()`).
- **Fake** — рабочая упрощённая реализация (in-memory БД, фейковые таймеры).
- **Тест-дабл** — общее название всего этого.

Правило: мокать **границы** (сеть, время, случайность, файловая система), а не внутренние функции. Чем больше моков, тем меньше тест похож на реальность и тем хрупче он при рефакторинге.

## Подробно

### В терминах Vitest/Jest

```js
const onSave = vi.fn();                 // mock/spy: записывает + можно задать поведение
onSave.mockReturnValue("ok");

const spy = vi.spyOn(api, "get");       // spy на реальный метод
spy.mockResolvedValue({ id: 1 });       // + stub поведения

vi.useFakeTimers();                     // fake time
vi.setSystemTime(new Date("2025-01-01"));
```

- `vi.spyOn(obj, "method")` — заменяет метод, сохраняя возможность `mockRestore()`.
- `vi.fn(impl)` — сразу с реализацией.
- `mockImplementation` / `mockReturnValueOnce` / `mockResolvedValue`.

### Что мокать

| Граница | Инструмент |
|---|---|
| HTTP | MSW / `vi.stubGlobal("fetch", ...)` |
| Время | `vi.useFakeTimers()`, `vi.setSystemTime` |
| Случайность | `vi.spyOn(Math, "random")` |
| UUID/ID | `vi.mock("uuid")` |
| Роутер / навигация | `MemoryRouter` |
| `localStorage` | jsdom + `vi.stubGlobal` |
| Модуль целиком | `vi.mock("./module")` |

### Что не мокать

- Внутренние функции своего же модуля — это тест реализации.
- React-хуки (`useState`) — тестируйте результат.
- То, что можно протестировать через настоящий API (лучше MSW).

### `vi.mock` и hoisting

```js
import { vi } from "vitest";

vi.mock("./config", () => ({
  API_URL: "http://test",
}));
```

- Вызовы `vi.mock` **поднимаются** в начало файла.
- Переменные вне фабрики недоступны (TDZ) — используйте `vi.hoisted`:

```js
const mocks = vi.hoisted(() => ({ get: vi.fn() }));
vi.mock("./api", () => ({ get: mocks.get }));
```

### MSW как «правильный» мок сети

```js
const server = setupServer(
  http.post("/api/login", async ({ request }) => {
    const body = await request.json();
    if (body.email === "anne@example.com") {
      return HttpResponse.json({ token: "t" });
    }
    return HttpResponse.json({ error: "bad" }, { status: 401 });
  }),
);
```

- Не зависим от реализации `fetch`/axios — работают все.
- Можно переопределять на конкретный тест: `server.use(...)`.
- Ошибки сети: `HttpResponse.error()`.

### Мок vs реальная интеграция

- Мок окупается, когда реальная граница недоступна/медленная/платная.
- Мок сети через MSW — дешёвая и точная замена.
- Мок модуля — быстрый, но хрупкий.

### Дубли и «тестовые данные»

- **Factory** (`createUser(overrides)`) — вместо ручных объектов в каждом тесте.
- **Builder** — для сложных сущностей.
- **Фикстуры** — JSON-данные на диске.
- Тестовые данные не должны содержать реальные персональные данные.

### Пример: тестирование утилиты с временем

```js
it("истекает через 7 дней", () => {
  vi.useFakeTimers();
  vi.setSystemTime(new Date("2026-01-01T00:00:00Z"));

  const token = createToken();
  vi.advanceTimersByTime(7 * 24 * 60 * 60 * 1000 + 1);

  expect(isExpired(token)).toBe(true);
  vi.useRealTimers();
});
```

> [!warning] Подвох
> «Смокал `fetch` вручную — почему тесты хрупкие?» — потому что мок привязан к форме вызова (`url`, `options`), и при переходе на `axios`/`ky` тесты падают, хотя поведение не менялось. MSW перехватывает сеть на уровне браузера/Node.
