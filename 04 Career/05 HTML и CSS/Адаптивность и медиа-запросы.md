# Адаптивность и медиа-запросы

## Краткий ответ (30 секунд)

Адаптивность — интерфейс, который работает на любом размере и контексте. Инструменты: 1) `meta viewport` (`width=device-width, initial-scale=1`); 2) **относительные единицы** (`rem`, `%`, `clamp()`, `svh/lvh` вместо `vh` на мобильных); 3) **flexible-грид** (`auto-fill` + `minmax`); 4) **медиа-запросы** по контрольным точкам (чаще mobile-first: `min-width`); 5) **container queries** — компонент реагирует на свой контейнер, а не на окно; 6) `prefers-reduced-motion`, `prefers-color-scheme`, `pointer: coarse`. Ключевая мысль: меньше breakpoints — лучше; компонент должен сам быть гибким.

## Подробно

### Viewport и единицы

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

- Без meta мобильный браузер «зумит» в 980px — сайт кажется мелким.
- **`vh` на iOS ломается** из-за адресной строки: для полноэкранных блоков — `dvh` (динамический), `svh` (минимальный), `lvh` (максимальный).
- `rem` — от корневого шрифта (удобно для масштабирования), `em` — от шрифта родителя (осторожно с вложенностью), `%` — от родителя.
- `clamp(min, предпочтительно, max)` — плавная типографика:

```css
h1 { font-size: clamp(1.5rem, 4vw, 3rem); }
```

### Медиа-запросы

```css
/* Mobile-first: базовые стили — мобильные, потом расширяем */
.grid { display: grid; grid-template-columns: 1fr; }
@media (min-width: 768px) {
  .grid { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 1200px) {
  .grid { grid-template-columns: repeat(4, 1fr); }
}
```

- `min-width` (mobile-first) проще поддерживать, чем `max-width`.
- Контрольные точки — по **контенту**, не по устройствам.
- `@media (hover: hover)` и `(pointer: fine)` — для hover-эффектов только там, где есть мышь.
- `@media (prefers-reduced-motion: reduce)` — отключение анимаций (a11y).

### Container queries (Baseline 2023)

```css
.card-container { container-type: inline-size; container-name: card; }

@container card (min-width: 400px) {
  .card { display: grid; grid-template-columns: 120px 1fr; }
}
```

- Компонент реагирует на **ширину родителя**, а не на viewport — идеально для переиспользуемых карточек в разных колонках.
- Нельзя контейнеризовать сам элемент, который запрашиваю (нужен обёртка).

### Гибридный подход

```css
/* Карточки без единого медиа-запроса */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(240px, 100%), 1fr));
  gap: 1rem;
}
```

### Адаптивные изображения

```html
<img src="m.jpg" srcset="s.jpg 480w, m.jpg 800w, l.jpg 1200w"
     sizes="(max-width: 600px) 100vw, 50vw" alt="..." width="800" height="600" />
```

См. [[Адаптивные картинки и изображения]].

### Что спросят

- «Чем отличается responsive от adaptive?» — responsive плавно подстраивается, adaptive — набор фиксированных макетов (реже, требует JS/серверных сигналов).
- «Почему `100vh` дёргается на мобильных?» — адресная строка → `dvh`/`svh`.
- «Как сделать компонент, не зависящий от окна?» — container queries.
- «Почему не стоит делать breakpoints под iPhone?» — разная ширина, поворот, планшеты; ориентир — контент.

> [!warning] Ловушка
> `@media (max-width: 767px)` + `@media (min-width: 768px)` — порядок важен, иначе «перекрытие». Лучше либо mobile-first (`min-width`), либо явные диапазоны (`768px <= width < 1024px` через `range` в новых браузерах).
