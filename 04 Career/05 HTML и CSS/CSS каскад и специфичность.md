# CSS каскад и специфичность

## Краткий ответ (30 секунд)

**Каскад** — алгоритм, который выбирает победителя среди правил для одного элемента. Порядок важности: 1) **происхождение и важность** (`!important` пользователя > `!important` автора > автор > пользователь > браузер); 2) **специфичность селектора**; 3) **порядок в источнике** (позже — побеждает). **Специфичность** считают как (id, классы/атрибуты/псевдоклассы, тип/псевдоэлементы): `#id` — `1,0,0`, `.a .b` — `0,2,0`, `div p` — `0,0,2`. `:where()` даёт нулевую специфичность, `:is()`/`:not()` — по самому специфичному аргументу, инлайн-стиль — сильнее любого селектора (но слабее `!important`).

## Подробно

### Порядок каскада (упрощённо)

1. **Origin & importance** (в порядке убывания силы): `!important` пользователя → `!important` автора → анимации (`@keyframes`) → обычный автор → обычный пользователь → пользовательский агент (браузер).
2. **Layers** (`@layer`): без слоёв — сильнее; слои сравниваются **в обратном порядке объявления** (последний слой сильнее). `!important` инвертирует порядок слоёв.
3. **Специфичность**.
4. **Порядок в источнике** (кто позже — тот прав).

Инлайн-стиль: специфичность выше любых селекторов (формально специфичность счётчика «инлайн»), но ниже `!important`.

### Как считать специфичность

| Селектор | Специфичность |
|---|---|
| `*` | 0,0,0 |
| `div` | 0,0,1 |
| `.card` | 0,1,0 |
| `[type="text"]` | 0,1,0 |
| `:hover` | 0,1,0 |
| `:not(.a)` | как `.a` → 0,1,0 |
| `:is(#a, .b)` | как `#a` → 1,0,0 |
| `:where(.a)` | 0,0,0 |
| `.a .b` | 0,2,0 |
| `#nav .link:hover` | 1,2,0 |
| `#id` | 1,0,0 |

- `:where()` **обнуляет** — удобно для «сброса» и базовых стилей библиотек.
- `:is()`/`:not()` берут специфичность **самого сильного аргумента**.
- `:nth-child(...)` — псевдокласс → `0,1,0`.
- Комбинаторы (`>`, `+`, `~`, пробел) специфичности **не добавляют**.
- Вложенность `&` (CSS Nesting) учитывает родителя как `:is(...)` — важно помнить.

### `!important` — когда

- **Почти никогда.** Исключения: исправление стилей сторонних виджетов, доступность (`@media (prefers-reduced-motion)`), утилиты-«фиксаторы».
- Лечить «не работает» через `!important` = накапливать техдолг: следующий разработчик добавит `!important` и ещё специфичнее.

### `@layer` — правильный инструмент вместо `!important`

```css
@layer reset, base, components, utilities;

@layer reset {
  button { background: none; border: 0; }
}

@layer components {
  .button { background: blue; color: white; }
}
```

- Порядок слоёв задаётся первой строкой; стили в `utilities` побеждают `components` без `!important`.
- **Неслоевые стили сильнее слоевых** — важная ловушка.
- `!important` в слое — инвертирует порядок (первый слой важнее).

### Инлайн и атрибут `style`

```html
<div style="color: red" class="text-blue">...</div>
<!-- красный: инлайн сильнее класса -->
```

`style=""` можно победить только `!important` в таблице стилей.

### практические правила

- Использовать **однородные классы** (БЭМ/utility), не `#id` для стилей (id — для якорей и JS).
- Избегать `!important`, доверять слоям и порядку.
- Проверять в DevTools: панель Styles показывает перечёркнутые правила и **специфичность**.

> [!warning] Подвох
> «Кто победит: `.a` и `div.a`?» — второй (0,1,1 против 0,1,0). «А `#a` и `.b.c.d`?» — id. «А `:where(.a)` и `div`?» — `div` (0,0,0 против 0,0,1).
