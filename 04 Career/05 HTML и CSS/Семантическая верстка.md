# Семантическая верстка

## Краткий ответ (30 секунд)

Семантическая верстка — использование элементов по их **смыслу**, а не по внешнему виду: `<nav>`, `<main>`, `<header>`, `<article>`, `<section>`, `<button>`, `<label>`. Это даёт доступность (скринридеры, клавиатура), SEO, бесплатное поведение из коробки (кнопка фокусируется и работает по Enter/Space), легче поддержку. Ключевое правило: **не див с `onClick`, если есть подходящий элемент**; один `<main>` на страницу; `<section>` — с заголовком; `<button>` для действия, `<a href>` — для навигации.

## Подробно

### Базовая структура документа

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>Магазин — Главная</title>
  </head>
  <body>
    <header>
      <nav aria-label="Основное меню">...</nav>
    </header>
    <main>
      <h1>Витрина</h1>
      <article>
        <h2>Товар дня</h2>
        <p>...</p>
      </article>
    </main>
    <footer>...</footer>
  </body>
</html>
```

- `<h1>` — один на страницу, иерархия заголовков правильная (`h1 → h2 → h3`, без пропусков).
- `<main>` — уникальный основной контент, один на документ.
- `<header>`/`<footer>` могут быть у разных секций, это нормально.
- `<article>` — самостоятельная единица (пост, карточка); `<section>` — тематический блок, почти всегда с `h2`.
- `<aside>` — второстепенное (реклама, «связанное»).

### `<button>` vs `<div>` vs `<a>`

```html
<a href="/orders">Заказы</a> <!-- навигация: URL меняется -->
<button type="button">Открыть модалку</button> <!-- действие на странице -->
```

- `<button>`: фокусируемый, `Enter`/`Space`, роль `button`, disabled.
- `<a href>`: ссылка, «открыть в новой вкладке», «скопировать адрес», поисковики.
- Див с `role="button"` требует ручной обработки клавиш — это почти всегда ошибка.

### Почему это важно для a11y

- Скринридер объявляет роль, имя и состояние («кнопка, меню, раскрыто»).
- Клавиатура: tab-порядок по DOM, `:focus-visible` для обводки, `Escape` для закрытия, ловушка фокуса в модалке.
- Форма: `<label for>` / обёртка, `autocomplete`, `aria-describedby` для подсказок, `aria-live` для сообщений.

### ARIA

**Правило №1:** нативный элемент лучше ARIA. Если нужна ARIA — она не заменяет поведение.

```html
<!-- ✅ нативно -->
<button aria-expanded="false">Меню</button>

<!-- ❌ ARIA без поведения -->
<div role="button" aria-expanded="false">Меню</div>
```

- `aria-label` — видимой подписи нет (иконка), `aria-labelledby` — ссылка на другой элемент, `aria-describedby` — дополнительное описание.
- `aria-hidden="true"` — скрыть декоративное от скринридера (но не `display: none` — тогда скрыто для всех).
- `role="status"`/`aria-live="polite"` — объявления без фокуса (тосты, счётчики).
- `aria-expanded`, `aria-selected`, `aria-checked` — состояния; обновляйте их со стейтом.

### Производительность и правда о «семантике»

- Семантика не влияет на FCP/LCP отрицательно; лишний DOM — влияет.
- SEO: `<main>`, заголовки, `<article>`, ссылки — реальные сигналы.
- `<picture>`/`srcset` — тоже «смысловая» разметка (см. [[Адаптивные картинки и изображения]]).

### Частые ошибки

- Несколько `<main>`.
- `<h1>` внутри `<header>` плюс ещё один `<h1>` в `<main>`.
- Кнопка без `type` внутри формы (`type="submit"` по умолчанию → неожиданный сабмит).
- `<a href="#" onClick>` вместо кнопки.
- Заголовки ради стилей (`h2` вместо `p` + класс).
- `aria-label` дублирует видимый текст или бесполезен («иконка»).

> [!tip] Как отвечать
> «Семантика — это роль элемента, не стиль. Скринридер видит `<button>` как кнопку, поэтому не дивы с обработчиками. Навигация — `<a href>`, действие — `<button>`. ARIA — только когда нет нативного элемента, и ARIA не заменяет поведение».
