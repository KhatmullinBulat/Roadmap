# 2. Явное

## Кратко

Явное преобразование — это когда разработчик сам указывает желаемый тип: `Number()`, `parseInt()`, `String()`, `Boolean()`, `!!`, `.toString()`. Такой код читается однозначно и не зависит от правил неявного приведения.

## Главное

### К числу

```js
Number("42") // 42 — строгий разбор всей строки
Number("42px") // NaN
Number(" 42 ") // 42 — пробелы по краям допускаются
Number("") // 0
Number(true) // 1
Number(null) // 0
Number(undefined) // NaN

parseInt("42px", 10) // 42 — читает до первого нечислового символа
parseFloat("3.14px") // 3.14
parseInt("10", 2) // 2 — явное основание
```

`Number()` строже: если в строке есть что-то, кроме числа (и пробелов), получается `NaN`. `parseInt()` мягче и поэтому подходит для «числа в начале строки», но требует основания `10`, иначе строки вида `"08"` в старых движках могли разбираться как восьмеричные.

```js
const input = "  12.5  "
Number(input) // 12.5
Number.isFinite(Number(input)) // true — надёжная проверка результата
```

Унарный `+value` короче `Number(value)` и делает то же самое, но обычно считается менее наглядным.

### К строке

```js
String(42) // "42"
String(null) // "null"
String(undefined) // "undefined"
(42).toString(2) // "101010" — основание системы счисления
`${42}` // "42" — шаблонная строка
```

Важно: `String(null)` и `String(undefined)` дают соответствующие строки, а `null + ""` даёт `"null"` тоже — но при `+` с объектом подключается `valueOf()`, что может дать другой результат.

### К логическому

```js
Boolean(0) // false
Boolean("0") // true — непустая строка
!![] // true
!!" " // true
```

Двойное отрицание `!!` — короткая запись `Boolean()`. Если в названии переменной уже видна булева природа (`isOpen`, `hasAccess`), писать `!!` при объявлении не обязательно.

### К объектам и примитивам

```js
Object(42) // Number {42} — обёртка, нужна редко
Symbol("id").description // "id" — описание символа
BigInt(42) // 42n — из числа, а BigInt(42.5) бросит RangeError
```

Конструкторы `new Number()`, `new String()`, `new Boolean()` создают **объекты-обёртки**, которые ведут себя иначе: `new Boolean(false)` истинно в условии. В новом коде их не используют.

### Как проверять то, что получилось

```js
const value = Number(input)

if (Number.isFinite(value)) {
  // это конечное число, а не NaN/Infinity
}
```

`Number.isFinite()` не приводит аргумент и возвращает `false` для строк, `NaN` и `Infinity`. Для целых значений есть `Number.isInteger()`.
