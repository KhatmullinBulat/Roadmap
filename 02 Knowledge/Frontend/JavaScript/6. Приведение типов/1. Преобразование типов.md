# 1. Преобразование типов

## Кратко

Преобразование типов — это смена типа значения: явная, когда разработчик вызывает `Number()`, `String()`, `Boolean()`, или неявная, когда её делает сам язык (`1 + "1"`, `if (value)`, сравнение `==`). Понимание правил неявного приведения позволяет предсказывать результат выражений и избегать странностей вроде `[] + {}`.

## Главное

JavaScript приводит значения к трём примитивным «целям»: числу, строке и логическому значению. Для объектов дополнительно работает механизм *ToPrimitive* — функция `ToPrimitive` вызывает у объекта методы `Symbol.toPrimitive`, `valueOf()` или `toString()` в порядке, зависящем от подсказки (`"number"`, `"string"`, `"default"`).

```js
Number("42") // 42 — явное
String(42) // "42" — явное
Boolean("") // false — явное

1 + "1" // "11" — неявное: число к строке
"5" * 2 // 10 — неявное: строка к числу
if (user) {} // неявное: значение к логическому
```

### Три цели преобразования

**К числу.** Срабатывает в арифметике, унарном `+`, `<`, `>` и в `Number()`. Правила строгие: `Number("42")` — число, а `Number("42px")` — `NaN`. Пустая строка превращается в `0`, `null` — в `0`, `undefined` — в `NaN`, `true` — в `1`.

```js
Number("") // 0
Number(null) // 0
Number(undefined) // NaN
Number(true) // 1
Number({}) // NaN
Number([]) // 0
Number([5]) // 5
Number([1, 2]) // NaN
```

**К строке.** Срабатывает при конкатенации с `+` и в шаблонных строках. Массив к строке — это `join(",")`, объект — `"[object Object]"`.

```js
String([1, 2]) // "1,2"
String({}) // "[object Object]"
`${[]}` // ""
```

**К логическому.** Срабатывает в условиях и у `Boolean()`. Ложными являются только `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`.

### ToPrimitive и Symbol.toPrimitive

Если подсказка `"default"` (так бывает у `+` и `==`), JavaScript сначала пробует `valueOf()`, затем `toString()`. Если подсказка `"string"` (шаблон, `String()`), порядок обратный.

```js
const price = {
  amount: 100,
  valueOf() {
    return this.amount
  },
  toString() {
    return `${this.amount} ₽`
  },
}

price + 50 // 150 — сработал valueOf
String(price) // "100 ₽" — сработал toString
`${price}` // "100 ₽"
```

`Symbol.toPrimitive` переопределяет порядок:

```js
const token = {
  [Symbol.toPrimitive](hint) {
    return hint === "string" ? "token" : 42
  },
}

`${token}` // "token"
+token // 42
```

### Порядок в выражении `+`

`+` перегружен: если хотя бы один операнд — строка, выполняется конкатенация; иначе — сложение. Объект сначала приводится к примитиву, и уже затем решается.

```js
1 + 2 + "3" // "33"
1 + (2 + "3") // "123"
[] + [] // ""
[] + {} // "[object Object]"
{} + [] // 0 в выражении-скрипте — {} трактуется как блок
```

Последний пример часто сбивает с толку: всё зависит от позиции `{}`. В выражении-скрипте `{}` может разбираться как блок кода, а не как объект. Поэтому такие примеры иллюстрируют прежде всего грамматику, а не приведение типов.

### Почему это важно

- Сравнение `==` делает неочевидные преобразования (`null == 0` ложно, `"" == 0` истинно).
- `Array.prototype.sort()` и `+` по умолчанию приводят к строке, из-за чего `[10, 9, 1].sort()` даёт `[1, 10, 9]`.
- `Number(" ")` равно `0`, но функция ввода пользователя часто даёт не `0`.

Лучше явно преобразовывать значения: `Number(value)`, `String(value)`, `Boolean(value)` — тогда намерение видно в коде.

## Практика
