# 2. V8

## Кратко

V8 — открытый движок JavaScript и WebAssembly от Google, использующийся в Chrome, Chromium-браузерах, Edge и Node.js. Он исполняет код через интерпретатор Ignition, оптимизирует горячие функции TurboFan и управляет памятью сборщиком мусора Orinoco.

## Главное

**V8** — движок JavaScript и WebAssembly с открытым исходным кодом, разрабатываемый Google. Впервые он вышел вместе с Chrome в 2008 году. V8 используется в Chrome и других браузерах на базе Chromium, а также в Node.js.

Движок разбирает JavaScript, сначала быстро исполняет его, а затем оптимизирует часто запускаемые участки. Для этого он использует JIT-компиляцию, внутренние кэши и сведения о фактических типах и формах объектов. Если код начинает вести себя иначе, V8 может деоптимизировать участок и выполнить его более универсальным способом.

V8 также управляет памятью: выделяет её под объекты и освобождает недостижимые значения с помощью сборщика мусора. Сборка может выполняться параллельно или инкрементально, однако некоторые её этапы всё равно способны кратко приостановить выполнение JavaScript.

V8 не равен браузеру и не является отдельной «виртуальной машиной на каждый контекст». Браузер создаёт изолированные контексты и процессы вокруг движка, а Node.js дополняет V8 серверными API и циклом событий.

### Из чего состоит V8

- **Ignition** — интерпретатор байткода. Он быстро запускает код и параллельно собирает профиль выполнения.
- **TurboFan** — оптимизирующий JIT-компилятор. Компилирует «горячие» функции в машинный код на основе профиля типов.
- **Orinoco** — семейство сборщиков мусора. Использует поколения (new space / old space), параллельную и инкрементальную сборку, чтобы сокращать паузы.
- **Sparkplug / Maglev** — промежуточные оптимизаторы: быстрая компиляция без peak-оптимизаций.

### Хранение объектов

V8 хранит объекты с *hidden classes* («картами») — описанием набора и порядка свойств. Объекты одинаковой формы разделяют карту и доступ к полям по фиксированному смещению. Изменение формы объекта на ходу (добавление свойств в разном порядке, `delete`) создаёт новые карты и может ухудшать оптимизации.

```js
// одинаковый порядок свойств → одна форма
const a = { x: 1, y: 2 }
const b = { x: 3, y: 4 }

// форма меняется после создания
const c = { x: 1 }
c.y = 2
```

### Важное для разработчика

- Новые объекты лучше создавать сразу с полным набором свойств.
- Не меняйте типы полей у одного объекта (`value = 1`, потом `value = "1"`).
- `delete` свойства переводит объект в словарный режим (dictionary mode) — избегайте его в горячем коде.
- Утечки памяти чаще всего связаны с удержанием объектов через замыкания, глобальные переменные или незакрытые обработчики.
