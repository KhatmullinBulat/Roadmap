# 2. Оператор typeof

## Кратко

`typeof` — унарный оператор, который возвращает строку с категорией значения: `"number"`, `"string"`, `"object"`, `"function"` и т.д. Он хорошо различает примитивы, но для объектов неточен: массив, дата и `null` дают `"object"`.

## Главное

Оператор `typeof` возвращает строку с категорией значения. Он удобен для проверки примитивов и функций, но не умеет точно различать большинство объектов.
```js
typeof 42 // "number"
typeof "text" // "string"
typeof 1n // "bigint"
typeof Symbol() // "symbol"
typeof undefined // "undefined"
typeof function () {} // "function"
typeof {} // "object"
```

Есть две формы записи: `typeof value` и `typeof(value)`. Вторая не является вызовом функции, но может сделать сложное выражение понятнее.
```js
typeof 50 + " квартир" // "number квартир"
typeof (50 + " квартир") // "string"
```

| Значение | Результат `typeof` |
| --- | --- |
| `undefined` | `"undefined"` |
| `null` | `"object"` |
| `true` | `"boolean"` |
| `42`, `NaN` | `"number"` |
| `1n` | `"bigint"` |
| `"text"` | `"string"` |
| `Symbol()` | `"symbol"` |
| функция или класс | `"function"` |
| массив, дата, объект | `"object"` |

`typeof null === "object"` — историческая ошибка, сохранённая ради совместимости. Проверяйте `null` через `value === null`, а массив — через `Array.isArray(value)`.

Особый случай: `typeof undeclaredName` возвращает `"undefined"`, не выбрасывая ошибку. Но это не относится к имени `let`, `const` или `class` во временной мёртвой зоне — там будет `ReferenceError`.
```js
typeof undeclaredName // "undefined"

{
  // typeof count // ReferenceError
  let count = 0
}
```

Для проверки конкретного класса иногда используют `instanceof`, но он зависит от цепочки прототипов и не подходит, например, для значений из другого realm (iframe). Выбирайте проверку по смыслу задачи: `Array.isArray`, `Number.isNaN`, `Object.hasOwn` или валидацию структуры объекта.

### Шпаргалка проверок

| Нужно проверить | Чем пользоваться |
| --- | --- |
| число | `typeof x === "number" && !Number.isNaN(x)` |
| конкретно `NaN` | `Number.isNaN(x)` |
| `null` | `x === null` |
| `undefined` или `null` | `x == null` или `x === undefined \|\| x === null` |
| массив | `Array.isArray(x)` |
| функция | `typeof x === "function"` |
| дата | `x instanceof Date` или `Object.prototype.toString.call(x)` |
| плайн-объект | `Object.getPrototypeOf(x) === Object.prototype` |
| ключ у объекта | `Object.hasOwn(x, key)` |

```js
function isPlainObject(value) {
  if (typeof value !== "object" || value === null) return false
  const proto = Object.getPrototypeOf(value)
  return proto === Object.prototype || proto === null
}
```

`Object.prototype.toString.call()` показывает внутренний тег `[object Array]`, `[object Date]`, `[object Null]` и работает надёжнее `typeof` для объектов:

```js
Object.prototype.toString.call([]) // "[object Array]"
Object.prototype.toString.call(null) // "[object Null]"
```

## Практика

- [ ] Прогнать все значения таблицы через `typeof` и сверить с ожидаемым
- [ ] Написать `isPlainObject` и проверить на массиве, дате и `Object.create(null)`
- [ ] Исправить `typeof x === "object"` для массива через `Array.isArray`
