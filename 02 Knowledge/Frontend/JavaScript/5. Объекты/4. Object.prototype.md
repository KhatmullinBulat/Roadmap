# Прототип Object

## Кратко

`Object.prototype` — корень цепочки прототипов обычных объектов; его собственный прототип `null`. Он даёт базовые методы вроде `toString()` и `hasOwnProperty()`, но безопаснее пользоваться статическими методами `Object` — `Object.hasOwn()`, `Object.keys()` и т.п.

## Главное

`Object.prototype` — объект, от которого по умолчанию наследуют обычные объектные литералы. Его собственный прототип равен `null`, поэтому он завершает цепочку прототипов для большинства обычных объектов.
```js
const user = {}
Object.getPrototypeOf(user) === Object.prototype // true
Object.getPrototypeOf(Object.prototype) === null // true
```

От `Object.prototype` приходят методы вроде `toString()`, `valueOf()`, `isPrototypeOf()` и устаревший `hasOwnProperty()`. Однако полагаться на вызов метода непосредственно у произвольного объекта опасно: свойство можно переопределить, а у объекта с `null`-прототипом его вообще не будет.
```js
const data = Object.create(null)
data.id = 1

// data.hasOwnProperty("id") // TypeError
Object.hasOwn(data, "id") // true
```

Для повседневной работы предпочитайте статические методы `Object`:
- `Object.hasOwn(object, key)` — проверить собственное свойство;
- `Object.keys()`, `Object.values()`, `Object.entries()` — получить перечисляемые собственные свойства;
- `Object.getPrototypeOf()` — прочитать прототип;
- `Object.defineProperty()` — задать дескриптор свойства.

Не расширяйте `Object.prototype` в коде приложения или библиотеки. Такое изменение влияет почти на все объекты в окружении, может конфликтовать с другим кодом и неожиданно появляться в `for...in`.

### Что лежит в `Object.prototype`

| Метод | Назначение | Чем заменить |
| --- | --- | --- |
| `hasOwnProperty(key)` | есть ли собственное свойство | `Object.hasOwn(obj, key)` |
| `isPrototypeOf(obj)` | проверка цепочки прототипов | `proto.isPrototypeOf` — ок, если вызов не подменяется |
| `propertyIsEnumerable(key)` | перечисляемое ли свойство | `Object.prototype.propertyIsEnumerable.call(obj, key)` |
| `toString()` | строковое представление | `Symbol.toStringTag` для кастомных классов |
| `valueOf()` | примитивное значение | переопределяется в своих классах |
| `__defineGetter__` и др. | устаревшие аксессоры | `Object.defineProperty` |
| `__proto__` | доступ к прототипу | `Object.getPrototypeOf` / `Object.create` |

### `for...in` и унаследованные свойства

`for...in` обходит и унаследованные перечисляемые свойства, поэтому в цикле обычно нужна проверка:

```js
for (const key in obj) {
  if (!Object.hasOwn(obj, key)) continue
  console.log(key)
}
```

Для собственных ключей проще сразу брать `Object.keys(obj)`, `Object.entries(obj)` или `Object.values(obj)`.

### Установка прототипа при создании

```js
const base = { kind: "base" }
const obj = Object.assign(Object.create(base), { id: 1 })
```

В литерале `{ __proto__: base }` тоже задаёт прототип, но это поведение легко случайно активировать из внешних данных. Явный `Object.create()` читается лучше.
