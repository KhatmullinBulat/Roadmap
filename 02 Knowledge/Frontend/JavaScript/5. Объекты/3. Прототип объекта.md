# Прототип объекта

## Кратко

У каждого объекта есть скрытое свойство `[[Prototype]]` — ссылка на другой объект или `null`. Если свойства нет у самого объекта, поиск идёт по цепочке прототипов; читать её обычно через `Object.getPrototypeOf()`, а создавать объект с нужным прототипом — через `Object.create()`.

## Главное

У каждого объекта есть внутреннее свойство `[[Prototype]]`. Оно содержит ссылку на другой объект или `null`. Его обычно называют **прототипом объекта**.

Когда свойство не найдено у самого объекта, JavaScript ищет его в прототипе, затем в прототипе прототипа и так до `null`. Это основа [[5. Прототипное наследование|прототипного наследования]].
```js
const animal = {
  eats: true,
}

const rabbit = Object.create(animal)
rabbit.jumps = true

rabbit.eats // true — найдено в animal
rabbit.jumps // true — собственное свойство
```

Прототип объекта можно прочитать через `Object.getPrototypeOf(object)`. Создавать объект с заданным прототипом удобно через `Object.create(prototype)`. `Object.setPrototypeOf()` существует, но менять прототип уже созданного объекта обычно не стоит: это медленно и усложняет код.
```js
Object.getPrototypeOf(rabbit) === animal // true
```

Свойство `__proto__` — исторический аксессор для `[[Prototype]]`. Его лучше не использовать: оно отсутствует у объектов с `null`-прототипом и может быть источником проблем при обработке внешних данных. В объектном литерале `__proto__: prototype` всё ещё можно встретить, но `Object.create()` выражает намерение яснее.

Прототип участвует в чтении свойства. Присваивание обычно создаёт или меняет собственное свойство объекта и не меняет свойство прототипа. Исключение — унаследованный сеттер: тогда присваивание вызовет его.
```js
const user = {
  set fullName(value) {
    [this.name, this.surname] = value.split(" ")
  },
}

const admin = Object.create(user)
admin.fullName = "Анна Иванова"
```

### Прототип без прототипа

Объект с прототипом `null` не наследует даже `toString` и `hasOwnProperty`. Это удобно как словарь с произвольными ключами:

```js
const dict = Object.create(null)
dict.__proto__ = "not a prototype"
Object.getPrototypeOf(dict) // null
```

Такой объект безопаснее обычного `{}`, если ключи приходят извне: ключ `__proto__` в данных обычного литерала может сработать как установка прототипа.

### Проверка цепочки

```js
Object.prototype.isPrototypeOf.call(animal, rabbit) // true
animal.isPrototypeOf(rabbit) // true — тот же смысл
rabbit instanceof Object // true
```

`isPrototypeOf()` проверяет наличие объекта в цепочке прототипов, а `instanceof` — то же самое, но через функцию-конструктор.

### Тонкость: чтение и запись

- Чтение идёт по цепочке вверх.
- Запись `obj.x = 1` создаёт **собственное** свойство и только тогда, когда такого свойства нет в цепочке или оно там не «только для чтения».
- Если в прототипе есть сеттер, присваивание вызовет его (пример выше).
- `delete obj.x` удаляет только собственное свойство, но не свойство прототипа.
