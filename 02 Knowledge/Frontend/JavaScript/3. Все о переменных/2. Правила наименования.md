# Правила наименования

## Кратко

Имя переменной — идентификатор: буквы, цифры, `$` и `_`, не начиная с цифры, с учётом регистра. Допустимое имя не всегда хорошее: оно должно объяснять назначение, поэтому в прикладном коде принято `camelCase` и осмысленные английские слова.

## Главное

Имя переменной — это идентификатор. Оно может содержать буквы Unicode, цифры, `$` и `_`, но не может начинаться с цифры. Регистр важен: `userName` и `username` — разные имена.
```js
const userName = "Bulat"
const $element = document.body
const _cache = new Map()

// const 2faEnabled = true // SyntaxError
```

В прикладном JavaScript обычно используют английские слова и `camelCase`:
```js
const totalPrice = 1_500
let isLoading = false
function getUserById(id) {}
```

Полезные соглашения:
- давайте переменным название по смыслу, а не по типу: `users`, а не `usersArray`;
- используйте `is`, `has`, `can` для булевых значений: `isOpen`, `hasAccess`;
- не сокращайте имя, если сокращение не общеизвестно в контексте (`index`, `event`, `id` обычно понятны);
- не используйте зарезервированные слова языка: `class`, `return`, `await` и другие;
- начальный `_` — только соглашение команды. Язык не делает такое свойство приватным.

Допустимые с точки зрения языка имена не всегда удачны для кода. Главное правило — имя должно объяснять назначение значения без дополнительного комментария.

### Регистры имени

| Стиль | Где используют | Пример |
| --- | --- | --- |
| `camelCase` | переменные и функции | `userProfile`, `getUser()` |
| `PascalCase` | классы и конструкторы | `class UserAccount` |
| `UPPER_SNAKE_CASE` | «настоящие» константы | `MAX_RETRIES` |
| `_private` | соглашение о внутреннем API | `_cache` |
| `#field` | действительно приватное поле класса | `this.#token` |

```js
class UserAccount {
  #token
  constructor(token) {
    this.#token = token
  }
}
```

### Чем проверять

- ESLint с правилами `camelcase`, `id-length`, `new-cap` ловит нарушения автоматически.
- Prettier и подобные форматтеры имени не меняют — это задача линтера.
- Имя свойства объекта и ключ в `Object.keys()` тоже участвуют в контракте API: переименование может сломать внешний код.
