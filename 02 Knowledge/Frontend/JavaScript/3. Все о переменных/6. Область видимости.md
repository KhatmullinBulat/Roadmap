# 6. Область видимости

## Кратко

Область видимости (scope) определяет, где доступно имя переменной, функции или класса. JavaScript использует лексическую область видимости: доступ зависит от места объявления, а не вызова, и поиск идёт от текущего блока наружу до глобальной области.

## Главное

**Область видимости** определяет, где в программе доступно имя переменной, функции или класса. При обращении к имени JavaScript ищет его сначала в текущей области, затем во внешних областях и останавливается, когда находит совпадение или достигает глобальной области.
```js
const siteName = "Roadmap"

function showName() {
  const message = `Проект: ${siteName}`
  console.log(message)
}

showName()
// console.log(message) // ReferenceError
```

### Основные виды
- **Глобальная область** — код верхнего уровня обычного скрипта. Глобальные имена легко конфликтуют, поэтому ими лучше не злоупотреблять.
- **Модульная область** — верхний уровень ES-модуля. Имя доступно только в этом модуле, пока его явно не экспортируют.
- **Функциональная область** — тело функции. Параметры и `var` принадлежат функции.
- **Блочная область** — блок в фигурных скобках: `if`, `for`, `while`, `switch` и просто `{ ... }`. `let`, `const` и `class` принадлежат ближайшему блоку.

```js
if (true) {
  const token = "abc"
  var legacyValue = 42
}

// console.log(token) // ReferenceError
console.log(legacyValue) // 42
```

Вложенная функция может читать переменные внешней функции. Это называется **лексической областью видимости**: доступ определяется местом, где функция была объявлена, а не местом, откуда её вызвали.
```js
function createGreeting(name) {
  return function greet() {
    return `Привет, ${name}`
  }
}

const greetBulat = createGreeting("Bulat")
console.log(greetBulat())
```

Такой доступ лежит в основе **замыканий** (подробнее — в roadmap [[JavaScript]]). Уменьшайте область видимости настолько, насколько позволяет задача: это делает состояние локальным и снижает риск конфликтов имён.

### Shadowing — затенение

Внутреннее объявление с тем же именем «закрывает» внешнее:
```js
const theme = "light"

function render() {
  const theme = "dark" // новая переменная, внешняя не меняется
  console.log(theme) // "dark"
}

render()
console.log(theme) // "light"
```

Это удобно, но при больших функциях затрудняет чтение: лучше избегать одинаковых имён в соседних областях, если это не осознанное решение.

### Неявные глобальные переменные

```js
function broken() {
  accidental = 42 // без объявления создаёт глобальную переменную
}
```

В строгом режиме и модулях такая строка даёт `ReferenceError`. Это одна из главных причин включать `"use strict"` и не использовать `var`.

## Практика

- [ ] Написать функцию, где блочная переменная скрывает внешнюю, и проверить вывод
- [ ] Убрать `var` из примера и проверить, что доступ вне блока исчез
- [ ] Найти в проекте глобальные утечки с помощью ESLint (`no-undef`, `no-implicit-globals`)
