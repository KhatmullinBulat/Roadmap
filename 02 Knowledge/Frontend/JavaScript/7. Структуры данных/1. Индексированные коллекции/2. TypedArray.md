# TypedArray

## Кратко

TypedArray — общее имя для семейства встроенных объектов (`Uint8Array`, `Int32Array`, `Float64Array` и др.), которые хранят числа одного типа в непрерывном буфере `ArrayBuffer`. В отличие от обычного `Array`, здесь нет «разных типов внутри», нет дыр, а каждый элемент занимает фиксированное число байт — поэтому TypedArray используют для бинарных данных, файлов, сетевых протоколов и WebGL.
Важно: `TypedArray` — это не класс и не глобальный конструктор, которым можно вызвать `new TypedArray()`. Это абстрактная «родительская» сущность: реальные классы — `Int8Array`, `Uint8Array` и т.д.
`new TypedArray()` бросит `TypeError`.

## Главное

### Зачем они нужны

Обычный `Array` — это объект с произвольными значениями и разреженными индексами. Для бинарных данных это неэффективно и неудобно: нужно самому считать байты, длины и порядок байт.
TypedArray решает три задачи:

- **Фиксированный формат.** Каждый элемент — число ровно одного примитивного типа (8/16/32/64 бита).
- **Непрерывная память.** Данные лежат подряд в `ArrayBuffer`, их можно передать в `fetch`, `File`, WebSocket, `WebAssembly` без преобразований.
- **Предсказуемая скорость.** Нет проверок типов на каждом элементе, как в обычном массиве.

### Виды TypedArray

| Класс | Диапазон значений | Размер | Тип элемента |
| --- | --- | --- | --- |
| `Int8Array` | -128 … 127 | 1 байт | `number` |
| `Uint8Array` | 0 … 255 | 1 байт | `number` |
| `Uint8ClampedArray` | 0 … 255, значения зажимаются | 1 байт | `number` |
| `Int16Array` | -32768 … 32767 | 2 байта | `number` |
| `Uint16Array` | 0 … 65535 | 2 байта | `number` |
| `Int32Array` | -2147483648 … 2147483647 | 4 байта | `number` |
| `Uint32Array` | 0 … 4294967295 | 4 байта | `number` |
| `Float16Array` | ±65504 (приблизительно) | 2 байта | `number` |
| `Float32Array` | ±3.4e38 (приблизительно) | 4 байта | `number` |
| `Float64Array` | ±1.8e308 (приблизительно) | 8 байт | `number` |
| `BigInt64Array` | -2^63 … 2^63 - 1 | 8 байт | `bigint` |
| `BigUint64Array` | 0 … 2^64 - 1 | 8 байт | `bigint` |

Все классы имеют статическое свойство `BYTES_PER_ELEMENT`: `Uint8Array.BYTES_PER_ELEMENT === 1`, `Float64Array.BYTES_PER_ELEMENT === 8`.

### `ArrayBuffer` — сам буфер

`ArrayBuffer` — это «сырой» кусок памяти фиксированной длины. Он не знает, что в нём лежит: байты, числа или текст. Читать его «как байты» напрямую нельзя — нужен view (TypedArray или `DataView`).

```js
const buffer = new ArrayBuffer(16) // 16 байт
buffer.byteLength // 16

// нельзя: buffer[0]
```

### Создание TypedArray

```js
const a = new Uint8Array(4) // 4 нулевых байта: [0, 0, 0, 0]
const b = new Uint8Array([1, 2, 3]) // из обычного массива
const c = new Uint8Array(buffer) // view на весь буфер
const d = Uint8Array.from([1, 2, 3]) // статический from
const e = Uint8Array.of(1, 2, 3) // статический of
```

Три способа задать view на часть буфера:

```js
const buf = new ArrayBuffer(8)

const view1 = new Uint8Array(buf) // весь буфер, 8 элементов
const view2 = new Uint8Array(buf, 2) // с байта 2 до конца, 6 элементов
const view3 = new Uint8Array(buf, 2, 3) // 3 элемента начиная с байта 2
```

Сигнатура: `new TypedArray(buffer, byteOffset = 0, length?)`. `byteOffset` должен быть кратен размеру элемента:

```js
new Int32Array(buf, 2) // RangeError: start offset of Int32Array should be a multiple of 4
```

### View и буфер — одна память

Несколько view могут смотреть на один и тот же буфер и видеть изменения друг друга:

```js
const buf = new ArrayBuffer(4)
const bytes = new Uint8Array(buf)
const words = new Uint16Array(buf)

bytes[0] = 255
words[0] // 255 — та же память, другое представление

words[1] = 256 // записали два байта
bytes[2] // 0
bytes[3] // 1
```

Именно поэтому TypedArray — быстрый способ прочитать бинарный формат: разбить буфер на части и интерпретировать каждую нужным типом.

### Свойства view

```js
const u8 = new Uint8Array([10, 20, 30, 40])

u8.length // 4 — число элементов
u8.byteLength // 4 — байт (length * BYTES_PER_ELEMENT)
u8.byteOffset // 0 — смещение в буфере
u8.buffer // ArrayBuffer
```

### Переполнение и преобразование

Значения за пределами диапазона не вызывают ошибку — они **обрезаются по модулю** (кроме `Uint8ClampedArray`, который зажимает):

```js
const u8 = new Uint8Array(1)
u8[0] = 300 // 300 % 256 = 44
u8[0] // 44

const i8 = new Int8Array(1)
i8[0] = 130 // 130 - 256 = -126
i8[0] // -126

const clamped = new Uint8ClampedArray(1)
clamped[0] = 300 // 255
clamped[0] = -5 // 0
```

Дробные значения обрезаются к нулю (`12.9 → 12`), а `NaN` и `Infinity` становятся `0`:

```js
const f = new Float32Array(1)
f[0] = 1.1 // хранится приближённое значение в float32
f[0] === 1.1 // false — точность ниже, чем у number (float64)
```

`Uint8ClampedArray` — стандарт для пикселей `ImageData`: они гарантируют, что значение попадёт в `0…255`, а не «перекрутится» через переполнение.

### Методы

TypedArray поддерживает большую часть методов `Array.prototype`: `map`, `filter`, `forEach`, `reduce`, `slice`, `sort`, `find`, `some`, `every`, `includes`, `indexOf`, `join`, `at`, `entries`, `keys`, `values`, `Symbol.iterator`.

Отличия:

- Результат `map`/`filter`/`slice` — **новый TypedArray того же типа**, а не обычный массив. Значит, `filter` на `Uint8Array` тоже обрежет значения.
- Нет `push`, `pop`, `shift`, `unshift`, `splice`, `concat`: длина фиксируется при создании.
- Нет `flat`, `flatMap`, `toSorted`, `toReversed`, `with`.
- Метод `set()` копирует данные из массива или другого TypedArray:
  ```js
  const u8 = new Uint8Array(4)
  u8.set([1, 2], 1) // [0, 1, 2, 0]
  ```
- Метод `subarray(start, end)` возвращает новый view на тот же буфер, без копирования. `slice()` — копирует.

```js
const full = new Uint8Array([1, 2, 3, 4])

const part = full.subarray(1, 3) // [2, 3], тот же buffer
part[0] = 99
full[1] // 99 — изменился исходный массив

const copy = full.slice(1, 3) // копия, независимая
```

### `DataView` — когда порядок байт важен

TypedArray читает числа в порядке своего платформы (обычно little-endian). Для сетевых протоколов нужен явный контроль, и тогда берут `DataView`:

```js
const buf = new ArrayBuffer(8)
const view = new DataView(buf)

view.setUint32(0, 0x12345678) // big-endian
view.getUint32(0) // 305419896

view.setInt16(4, -1, true) // little-endian
view.getInt16(4, true) // -1
```

### `SharedArrayBuffer`

`SharedArrayBuffer` — тот же буфер, но разделяемый между потоками (Web Workers). Требует изоляции контекста (заголовки COOP/COEP) и обычно работает вместе с `Atomics` для синхронизации.

```js
const sab = new SharedArrayBuffer(1024)
const counters = new Int32Array(sab)

Atomics.add(counters, 0, 1)
```

### Где встречается на практике

- `fetch` → `arrayBuffer()` → `new Uint8Array(...)` для бинарных ответов;
- `File`/`Blob` и `FileReader` (`readAsArrayBuffer`);
- `TextEncoder`/`TextDecoder`: `new TextEncoder().encode("привет")` даёт `Uint8Array`;
- `crypto.subtle` возвращает `ArrayBuffer`;
- WebGL/WebGPU: буферы вершин и индексов;
- Node.js: `Buffer` — подкласс `Uint8Array`;
- WebAssembly: `Memory` — `ArrayBuffer`.

```js
const bytes = new TextEncoder().encode("привет") // Uint8Array
bytes.length // 12 — UTF-8, по 2 байта на кириллическую букву

new TextDecoder("utf-8").decode(bytes) // "привет"
```

### Ограничения

- Нет дыр и «разных типов»: всё приводится к типу view.
- Длина фиксирована: рост возможен только созданием нового буфера.
- Переполнение молча обрезается — легко получить неверные числа без ошибки.
- `Float32Array` теряет точность по сравнению с `number` (`Float64Array`).
